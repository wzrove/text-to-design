# 输出模板与采纳前自检

> 何时读：工作流第 6 步要出结论时；或者结论成形了、准备建议采纳前。

## 输出模板

```markdown
## 压力
<具体代码/架构压力；变化频率、失败后果、当前已产生的成本>

## 结论
<主模式>（必要时：<辅助模式>），或明确写「不引入模式，保持 <更简单的做法>」

记录：<docs/design-decisions/NNNN.md>（本次是新建 / 追加 / 取代 / 废弃）

## 理由与排除
- 命中信号：<可观察证据，别写"最佳实践">
- 排除 <最相近候选>：<为什么>

## 实施方案

**目标形状（全量）**：角色与职责 / 接口所在层与依赖方向 / 创建与装配位置 / 一次请求或消息的调用时序 / 扩展点留在哪

**本次不做**：<明确列出>（扩展点留缝，但不预先实现）

## 成本与退出条件
<新增间接层、状态、网络跳数、存储、运维负担>；<需求规模下降或假设不成立时如何回退>

回退要能真执行：切换开关能关、兼容层和临时转换代码能删。只写「可以回退」但没有执行路径，等于没写。

## 验证
<不变量测试、边界/并发/重试用例、需要打的指标与日志>
```

异步模式（事件、Outbox、Saga、CQRS、重试）必须在「验证」里写明重复、乱序和恢复策略。

**「验证」段要填能追溯的证据**，不是把原则复述一遍。具体填什么看项目用什么手段
（复现用例与 id、失败信号、回归批次号、压测或灰度结果都行），唯一的要求是**别人照着能重跑一遍**。

## 采纳前自检

输出建议之前确认：

- [ ] 压力是真实的（已有 ≥2 个实现/分支，或已经出过回归），不是「以后可能会变」。
- [ ] 至少比较过一个相近候选，并说明了排除理由。
- [ ] 更简单的方案（函数、参数、组合、平台能力）已被明确排除。
- [ ] 团队能测试和观测新增的间接层；异步模式已说明重复/乱序/恢复。
- [ ] 「实施方案」写明了目标形状和「本次不做」的边界：扩展点留缝，但不预先实现。
- [ ] 结论已落入设计决策日志：新建记录，或在既有记录上追加变更/取代/废弃。

任何一项没通过 → 回到 SKILL.md 的「停止条件」，优先保持简单。
