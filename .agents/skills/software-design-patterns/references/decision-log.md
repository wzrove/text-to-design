# 设计决策日志：位置、写法、演进

> 何时读：要落一条决策记录、要处理需求变更（追加 / 取代 / 废弃），
> 或者要维护索引体积时。

SKILL.md 只留「结论必须落日志」这条纪律和当前位置，完整机制在这里。

## 位置

先沿用项目已有的约定，按这个顺序找：`docs/design-decisions/`、`docs/adr/`、
`docs/decisions/`、`ADR/`，或者项目里已有的设计日志。都没有，才新建
`docs/design-decisions/`，索引叫 `INDEX.md`。
这个顺序和 `scripts/new_decision.mjs` 里的 `CANDIDATE_DIRS` 一致，改一处记得同步另一处。

位置定下来之后**不要中途搬家**。标识会被外部引用（其他文档、变更记录、项目的缺陷台账都算），
路径一变引用就断。本技能只保证**记录格式和标识稳定**，至于谁按什么方式回填，
那是调用方和项目工具链的事。

## 创建记录

```bash
node scripts/new_decision.mjs "支付渠道分支改用 Strategy"          # 自动取短 id + 更新索引
node scripts/new_decision.mjs "订单状态机改用 State" --supersedes 0001
node scripts/new_decision.mjs "..." --dir docs/adr                # 目录与项目既有约定不同时
node scripts/new_decision.mjs --status 0001 已采纳                # 只改状态，不新建记录
```

标识两套并存：**新记录**用 `randomUUID` 前 8 位十六进制（`a1b2c3d4-标题.md`），
**旧记录**保留原 4 位数字号，文件名与既有引用一律不改。取号不读目录里的最大值——
多人各自开分支时 `max+1` 必然撞号，而短 id 不共享计数器；脚本再用
`O_CREAT|O_EXCL`（Node 的 `fs` flag `wx`）独占占位，同机同一秒各跑一次也只有一个赢家。
`--status` / `--supersedes` 两种形态都认。脚本零依赖，只用 Node 内置模块。

脚本从 [../assets/decision-record-template.md](../assets/decision-record-template.md) 生成骨架
（压力 / 候选与排除 / 结论 / 实施方案 / 成本与退出条件 / 验证 / 变更历史），填内容即可。
标识永不复用，不覆盖已有文件，新行只落在 INDEX.md 的表格区间内，不会插到「依赖关系」后面；
数字行按号插到该在的位置，短 id 行没有可比顺序，一律追加到表尾。行首写成 `[标识](文件名)`——
编号列一直是可达链接，裸标识会让新行在整张表里看起来像没登记。
带 `--supersedes` 时脚本会把原记录状态改成「已被取代」，同时同步 INDEX 那一行；
标识找不到就告警，不静默跳过。

`--status` 是唯一改状态的入口，记录正文和 INDEX 行一起改，省得两处对不上。
它只接受模板里那四个值 `提议 / 已采纳 / 已被取代 / 已废弃`。状态是封闭词表，
工作流第 1 步要靠它扫「仍在生效」的记录，所以拼错必须报错，不能静默写进去。

## 需求变更时的三种动作

| 情况 | 动作 |
|---|---|
| 结论不变，只是约束/规模变化 | 在原记录「变更历史」追加一行：日期、需求变更、结论是否变 |
| 结论变了 | 新建记录并 `--supersedes <原标识>`；原记录状态改为「已被取代」，保留原文 |
| 命中原记录的「退出条件」 | 原记录状态改为「已废弃」，新建记录写明回退方案与回退后的更简单设计 |
| 方案落地、提议转已采纳 | `--status <标识> 已采纳`（只改状态，正文靠原记录保留） |

**复盘触发**：每次需求变更之后，把相关记录的「退出条件」重扫一遍。命中了就回退，
不要因为已经实现过就继续留着模式。
**禁止**删除或静默覆盖旧记录，也别只改结论不写理由。

## 体积治理（索引是每次决策都要先读的文件）

`INDEX.md` 读取频率最高（工作流第 1 步），所以它的体积上限比单条记录严得多。

**先定职责，再定阈值**：索引只做**定位** —— 编号 → 标题 → 状态取值 → 影响范围粗粒度 → 日期。
膨胀基本都不是条数，是把正文抄进了索引，三条口径：

- **状态列** = 封闭词表值 + 最多一个 ≤12 字短标注（如 `已采纳（真机待验）`）。耗时、测试例数、日期、
  文件名、嵌套链接都不进索引 —— 验证叙事归那条记录的「验证」段与它自己的状态行。
- **影响范围列** = 层 / 包粒度（`shared/core`、`ui/code/<平台>`）。逐文件清单归记录的「实施方案」段。
- **依赖关系图** = 每条一行，只写关系（依赖 / 沿 / 取代 / 修订）+ 编号。
  「沿 00xx 的取向、撞 00xx 的口径」这类论证摘要归记录的「相关记录」行和「候选与排除」表。

| 阈值 | 动作 |
|---|---|
| 单条记录「变更历史」> 10 行 | 早期历史压成一行摘要 + 指向被取代的记录标识；历史靠链路保留，不靠正文堆叠 |
| `INDEX.md` > 15 KB 或 > 40 条 | 按年拆 `INDEX-2026.md`，主 INDEX 只留「现行有效 + 最近 10 条」 |
| 索引**单行**过宽（经验值 > 400 B） | 该行在抄正文：按上面三条瘦身。条数没超也会顶破总量阈值，光靠拆档治不了 |
| 依赖图单行 > 160 B | 行里写的是论证不是边 |
| `INDEX.md` 的「依赖关系」图 | 只画现行有效的记录；已取代 / 已废弃的不进图（否则图会无限加行） |

阈值由**项目自己**的文档预算校验守着（本技能不假设项目用哪套 CI 或测试框架）。
超了就在下一次决策之前按上表压缩，别等索引变成噪音源才处理。
