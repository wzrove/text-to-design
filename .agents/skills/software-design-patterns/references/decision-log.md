# 设计决策日志：位置、写法、演进

> 何时读：要落一条决策记录、要处理需求变更（追加 / 取代 / 废弃），
> 或要维护索引体积时。

SKILL.md 只保留「结论必须落日志」这条纪律与当前位置，本文是完整机制。

## 位置

优先沿用项目已有约定，按序找：`docs/design-decisions/`（本仓采用）、`docs/adr/`、
`docs/decisions/`、`ADR/`、已有设计日志。都没有才新建 `docs/design-decisions/`，索引为 `INDEX.md`。

位置一旦定下就**不要中途搬家** —— 编号会被外部引用（其他文档、变更记录、项目的缺陷台账），
路径一变引用就断。本技能只保证**记录格式与编号稳定**，不关心谁按什么方式回填（那是调用方
与项目工具链的事）。

## 创建记录

```bash
python3 scripts/new_decision.py "支付渠道分支改用 Strategy"          # 自动编号 + 更新索引
python3 scripts/new_decision.py "订单状态机改用 State" --supersedes 0001
```

脚本从 [../assets/decision-record-template.md](../assets/decision-record-template.md) 生成骨架
（压力 / 候选与排除 / 结论 / 最小落地 / 成本与退出条件 / 验证 / 变更历史），填内容即可。
编号永不复用，不覆盖已有文件。

## 需求变更时的三种动作

| 情况 | 动作 |
|---|---|
| 结论不变，只是约束/规模变化 | 在原记录「变更历史」追加一行：日期、需求变更、结论是否变 |
| 结论变了 | 新建记录并 `--supersedes <原编号>`；原记录状态改为「已被取代」，保留原文 |
| 命中原记录的「退出条件」 | 原记录状态改为「已废弃」，新建记录写明回退方案与回退后的更简单设计 |

**复盘触发**：每次需求变更后，重扫相关记录的「退出条件」。命中就回退，不要因为已经实现过就继续保留模式。
**禁止**删除或静默覆盖旧记录，也禁止只改结论不写理由。

## 体积治理（索引是每次决策都要先读的文件）

`INDEX.md` 的读取频率最高（工作流第 1 步），所以它的体积上限比单条记录严得多：

| 阈值 | 动作 |
|---|---|
| 单条记录「变更历史」> 10 行 | 早期历史压成一行摘要 + 指向被取代的记录编号；历史靠链路保留，不靠正文堆叠 |
| 单条记录 > 12 KB（**软上限，只告警不判红**） | 压缩「变更历史」；把稳定的证据表 / 复核清单移出正文。**不要为了过线删掉结论与排除理由** —— 证据是决策记录的全部价值。持续告警而无人处理时才考虑升级为硬上限 |
| `INDEX.md` > 15 KB 或 > 40 条 | 按年拆 `INDEX-2026.md`，主 INDEX 只留「现行有效 + 最近 10 条」 |
| `INDEX.md` 的「依赖关系」图 | 只画现行有效的记录；已取代 / 已废弃的不进图（否则图会无限加行） |

阈值由仓库根 `tests/skill-doc-budget.test.ts` 守着，硬线超了 CI 会红；软上限只在输出里告警。
