# 设计模式决策指南

仅在 SKILL.md 的「快速路由」未命中、问题跨多个层级、或需要评分/迁移顺序时读取。
停止条件和输出格式见 SKILL.md，不在此重复。

## 1. 先判断问题属于哪一层

| 问题层级 | 典型问题 | 优先查看 |
|---|---|---|
| 对象创建 | 创建逻辑复杂、需要切换实现、参数很多 | Factory Method / Abstract Factory / Builder / Prototype / DDD Factory |
| 类与对象组合 | 第三方适配、功能包装、访问控制、树结构 | Adapter / Decorator / Proxy / Composite / Facade / Bridge |
| 行为变化 | 算法切换、固定流程、规则链、状态变化 | Strategy / Template Method / Chain / State / Command |
| 应用分层 | 事务、持久化隔离、接口契约 | Service Layer / Repository / Unit of Work / DTO / DI |
| 领域建模 | 身份、值、不变量、聚合、领域规则 | Entity / Value Object / Aggregate / Domain Service / Specification |
| 跨服务可靠性 | 双写、重试、故障隔离、跨服务事务 | Outbox / Idempotency / Retry / Timeout / Circuit Breaker / Bulkhead / Saga |
| 读写架构 | 写规则复杂、读模型特殊、审计重放 | CQRS / Event Sourcing |

跨层问题按上表从上到下拆：先修边界（建模/分层），再隔离变化（创建/组合/行为），最后加可靠性机制。顺序反了会让模式掩盖错误的职责划分。

## 2. 评分与证据门槛

候选模式进入实施方案前先做轻量评分。评分不是数学真理，而是迫使设计讨论显式化；任何一项没有证据都记 0，不按"未来可能"加分。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 变化压力 | 没有重复或变化 | 已出现 2 个实现/分支 | 变化频繁且修改容易回归 |
| 边界收益 | 无边界问题 | 能隔离一个局部依赖 | 能保护跨模块/事务/安全不变量 |
| 测试收益 | 更难测 | 可替换一个外部边界 | 可建立稳定的合同/状态测试 |
| 运行时成本 | 需新增网络/持久化/全局状态 | 新增少量间接层 | 需要异步、租约、投影或运维体系 |

总分低于 3，或"运行时成本"达到 2 而没有对应可靠性/一致性收益时，默认保持简单。分数高也不能替代领域边界判断：先解决错误的职责归属，再考虑模式。

## 3. 从现状到模式的迁移顺序

优先采用可回退的切片：

1. 补基线测试和指标，作为差分依据。
2. 提取稳定端口（接口 + 装配点），旧的调用路径先保留。
3. 迁移一个调用路径，对比新旧结果。
4. 确认无回归后删除旧分支。

对于事件、Outbox、Saga、CQRS 等模式，必须先定义事件/命令版本、重复处理和失败恢复，再扩大覆盖面；不能让新旧两条事实源长期并存。
