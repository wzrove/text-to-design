# 指纹算法

> 何时读：怀疑指纹归并过粗 / 过细，看到不该 `suppressed` 的项，
> 或想改归一化规则时（改规则会让所有既有指纹失效）。

报错身份 = `sha1(tool + "\0" + normalize(message)).slice(0, 12)`

工具名是独立分量,所以同一条文案出现在不同工具上是**两条**不同的错误。

## 归一化规则

按顺序应用,把可变片段替成占位符:

| 规则 | 匹配 | 替换 |
| --- | --- | --- |
| 工具名 | 文案里出现的 `--tool` 值 | `<tool>` |
| 反引号内容 | `` `xxx` `` | `<v>` |
| 中文引号内容 | `「xxx」` | `<v>` |
| 双引号内容 | `"xxx"`(≤120 字符) | `<v>` |
| 单引号内容 | `'xxx'`(≤120 字符) | `<v>` |
| 节点 id | `\d+:\d+`(如 `23:1456`) | `<id>` |
| 长十六进制 | `[0-9a-f]{8,}`(uuid / hash) | `<id>` |
| 长数字 | `\d{4,}`(端口、耗时、偏移) | `<n>` |
| 连续空白 | 换行/多空格 | 单个空格 |

结果为空串时退回原始文案,避免所有空文案塌缩成同一个指纹。

## 样例

| 原始文案 | 归一化后 |
| --- | --- |
| `参数校验失败(jsd_set_fill_color): color: 必须是非空字符串` | `参数校验失败(<tool>): color: 必须是非空字符串` |
| `没有找到组件: 23:1456` | `没有找到组件: <id>` |
| `没有找到组件: 88:999` | `没有找到组件: <id>`(同上,归并) |
| `请求超时: r431 jsd_export 耗时=30021ms` | `请求超时: <id> <tool> 耗时=<n>ms` |
| `端口 47820 被非 text-to-design MCP 服务占用,请先释放` | `端口 <n> 被非 text-to-design MCP 服务占用,请先释放` |
| `分组至少需要 2 个节点` | 原样(2 只有 1 位,不抹) |
| `未知图标:foo-bar(可用 jsd_list_fonts 查)` | 原样(`foo-bar` 没有引号包裹) |

## 已知取舍

**故意的过粗**:`\d{4,}` 会把 `300x200` 这类尺寸里的 4 位数也抹掉,让两条本可区分的
文案归并成一条。这偏保守 —— 宁可少建几条待办,也不要把同一类错误拆成一屏噪音。

**故意的不过粗**:参数值本身参与指纹。`未知图标:foo-bar` 与 `未知图标:baz-qux`
是两条待办。因为不同图标名失败可能指向不同根因(别名表缺项 vs 查询逻辑 bug),
交给人工看 `样例入参` 合并更稳。

**不会自动归并的同义文案**:`没有找到组件: <id>` 与 `组件不存在` 是两条指纹。
文案改写会导致旧指纹不再命中 —— 若你顺手改了报错措辞,已闭环的那个指纹会"失联",
新文案会作为新错误重新入账一次。这是预期行为:文案变了就是新的可观测事实,
重新记一次并 `handle` 掉即可,不必去手改 `handled.json`。

## 自检

怀疑归并行为时,直接看 `list` 输出的 `骨架` 行 —— 那就是归一化结果。
两条记录的骨架一模一样却没有归并,说明工具名不同(工具名是独立分量)。

要验证某个假设,可临时用 `MCP_TDD_ROOT` 指向空目录做沙盒实验,不影响真台账:

```bash
MCP_TDD_ROOT=/tmp/mcp-tdd-sandbox node $S init
MCP_TDD_ROOT=/tmp/mcp-tdd-sandbox node $S record --tool jsd_x --error '...'
MCP_TDD_ROOT=/tmp/mcp-tdd-sandbox node $S list
```

改了归一化规则(`scripts/mcp-tdd.mjs` 的 `normalize()`)会让**所有既有指纹失效**,
等价于把台账清零。真要改就得同时迁移 `errors.jsonl` 与 `handled.json` 里的指纹,
别单独改函数。
