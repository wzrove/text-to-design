# 0042. 本地样式枚举按类拆分：同步 getter 不可中断，单类入口兼作定位探针

- **日期：** 2026-10-10
- **状态：** 已采纳（三包类型检查通过 + 4 例单测通过；探针已跑，**机制描述于 2026-10-15 更正**：永挂的是 `*Async` 成员不是同步 getter，见「变更历史」）
- **影响范围：** `shared/`（新增 `dicts/style-kind.ts`、`schemas/{inputs,results}.ts`、`core/{access,export}.ts`、`dicts/index.ts` 出口、新增 `__tests__/list-styles.test.ts`）、`ui/`（`code/plugin.ts` 的 `list_styles` 分发）、`mcp-server/`（`tools/resources.ts` 新增 `jsd://styles/{kind}` 模板）
- **相关记录：** 0007（不允许静默失效）、0011（跨页读门控与异步入口）、0032（平台差异只落声明表与投影点）、0039（`get_page` 把样式枚举带进了默认路径）

## 压力

**一条被「四类全调」掩盖的平台缺陷，加上一个由它暴露的可用性回归。**

2026-10-10 在即时设计（jsDesign）上跑 0039 的真机验收，`get_page` 复现了它当初要修的那个症状：

```
r7  get_page     ok=false 耗时=25024ms error=forward_timeout
r10 list_styles  ok=false 耗时=25008ms error=forward_timeout
```

拆开看，两件事必须分开说：

1. **0039 真正修的那半是好的。** `find` 把本页 **3346 个节点**全读回来只用 **99ms** —— 节点枚举、序列化、传输都健康，「每节点跨边界属性读顶穿预算」那半确实修掉了。
2. **卡住的是样式枚举。** `listStylesAsync` 对四类（PAINT / TEXT / EFFECT / GRID）**逐个**先试 `*Async`（0010「有 async 就用 async」），**只有该成员不存在时才退同步 getter**。jsDesign 的 typings 只有同步版（`plugin-api.d.ts:95-98`），但运行时四个 `*Async` 都在 ⇒ `?.` 判断成立 ⇒ `await` 一个**永挂的 Promise** ⇒ 撞满 25s 转发上限（25s 是 UI 侧定时器到点，不是引擎结束），`catch` 与 `setTimeout` 都等不到任何东西。

**判别「数据相关还是平台相关」的实验**（用户新建空文件后复测）：空文档（`find` 返回 `total: 0`）上 `list_styles` **照样 25005ms 超时** → **平台相关，与文档内容无关**。

⚠ **本条当时把「缺的是谁」判错了两次**（2026-10-15 真机更正，详见「变更历史」）：

- **「卡住的是同步 getter」指错了对象** —— 四类同步 `getLocal*Styles` **直接调全部 0~1ms 正常返回**（PAINT 6 / TEXT 1 / EFFECT 0 / GRID 0），在事故路径里它们**根本没被调用过**（`?.` 一成立就走 async 那条了）。永挂的是 `getLocal*StylesAsync`：那条调用**永不 resolve**。挂着的是 Promise ⇒ **线程并不冻死**（两次超时之间别的调用照常），「调用即冻死线程」这句也是错的。
- **「我们自己在调不存在的异步入口」这条排除错了** —— 它是按 **typings** 判断 `?.` 会不会跳过（host 是 `Object.create(native, ...)`、没有 Proxy 门面，`jsdesign/host.ts:26`），而 **typings 里没有 ≠ 运行时没有**：原生成员整个透出来，四个 `*Async` **运行时都在**（真机：四个 `typeof === 'function'`），`?.` 根本没跳过它们。正是这条错判把「没回音」安到了同步 getter 头上。

**回归点（本记录的直接动机）**：`jsd://styles` 的超时在 0039 之前就存在（只是没人报），但 0039 把 `listStylesAsync` 放进了 `get_page` 的 `assets` 默认路径 —— 于是**即时设计上 `get_page` 全废**（不是大文档才废，空文件也废），而它是「设计前第一步」的入口。

## 候选与排除

| 候选 | 结论 | 排除理由 |
|---|---|---|
| 给挂住的那条路加超时 / 返回空 | 排除 | **对象找错时就谈不上成立**：当时以为挂的是同步 getter（同步调用确实不可中断 —— 插件线程在它返回前是冻结的，`catch` 与 `setTimeout` 都不会被调度到，这句要留在注释里，否则下一个人还会想加 timeout）；2026-10-15 真机证明挂的是**永不 resolve 的 async 成员**：`await` 不抛也不 settle，`Promise.race` 超时也只能放弃这次调用。两条路唯一的共同点是 —— **判断必须在调用前做出** |
| 调用点逐个 try/catch 后返回空（= 最初的想法） | 排除（作为**默认**） | **撒谎**：与变量面不同 —— 变量是「平台没有这个 API」，**不需要问**就知道答案是空；样式是「问了没回音」，文档里很可能真有一堆样式（按 id 应用样式仍然正常）。静默返空会被读成「这文档没有样式」，是假结论。若探针证明是平台性读不出，可以返空，但**必须带 `note` 点名** |
| 按类拆分 + 单类入口（本批） | 采用 | — |
| 直接给 `get_page` 加 `includeStyles?` 默认关 | 本批不做 | 结论依赖探针结果：若四类里只有一两类挂死，正确修法是「跳过挂死的那几类」而不是「整体关掉」；先看到证据再定 |
| 新增 `jsd_list_styles` 工具 | 排除 | 样式此前刻意只走资源（`jsd://styles`），加一个有同名能力的工具会造出第二个出口（0020 的取向） |

## 结论

**不引入模式。** 把「四类」从「一次批量查询」还原成**四次独立调用**，并给出口加一个 `kinds` 筛选；单类入口同时就是定位探针 —— 分开问，才谈得上「坏的是哪一个」。

关键纪律：`kinds` 必须是**跳过**没选中的类别，**不是取回来再过滤**。否则挂死的那一类照样会被调起来，探针就毫无意义（单测断言的是**调用记录**，不是返回值）。

## 实施方案

- **目标形状**
  - `dicts/style-kind.ts`：`STYLE_KINDS` / `StyleKind` 单一真源，供枚举结果的**取值域**与入参的**筛选域**共用（两处漂了不会报错，只会让「按 TEXT 筛」悄悄少一类；形制同 `dicts/search-scope.ts`）。
  - `core/access.ts` 的 `listStylesAsync(host, kinds?)`：四类各自带 `kind`，未选中的在**调用前**跳过；在同步入口处写死那句「不可中断 ⇒ 按 kind 少问不是优化，是可用性前提」。
  - `core/export.ts` 的 `listStyles(host, kinds?)` 透传；`plugin.ts` 的 `list_styles` 分发透传 `params.kinds`。
  - `mcp-server`：新增**单类资源** `jsd://styles/{kind}`（`jsd://styles` 保持不变，语义仍是「全部」）。
- **本批做**：上述按类拆分 + 单类入口 + 4 例单测。
- **本批不做**（**依赖探针结果**）：`get_page` 的 `assets` 是否摘掉 / 加 `includeStyles?`；jsDesign 的 `assets.styles` 是否恒空 + `note` 点名；四个 getter 里到底哪几个不返回。

## 成本与退出条件

- **成本**：多一个 dict 文件与一个参数；`jsd://styles/{kind}` 多一个资源条目（资源不进工具目录，不占目录体积门禁）。
- **退出条件**：若探针证明**四类全都不返回**，「按类拆」对即时设计就没有救回任何东西 —— 那时 `kinds` 仍留着（对 Figma 有用，且是实现「跳过挂死类」的前提），但 `get_page` 必须走「默认不枚举样式」；若探针证明**只有部分类挂死**，则退化为按平台的跳过清单，`kinds` 成为常规筛选。

## 验证

- **不变量测试**（`__tests__/list-styles.test.ts`，4 例）：不给 `kinds` 四类全问；只给一类时**其余三类一次都不调**；给两类时只调这两类；getter 缺失的类别跳过而不报错（与「没选中」区分开）。
- **真机探针（2026-10-15 已跑，探针随后删除）**：四类 `getLocal*Styles` 直接调全部 0~1ms 返回 ⇒ 挂住的不是某一类，而是 `*Async` 那条选路（见「变更历史」与 e1e66f0a）。
- **顺带确认**：`jsd://styles`（全部）在 Figma 上仍正常（此前实测返回 `{styles: [], count: 0}`）。
