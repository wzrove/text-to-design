## 压力

新增 code 模式要求 frontend/backend 子模式及后续扩展；当前只有外部 AI 操作设计插件的产品链路，没有聊天 Session、Workspace 或代码执行器。现有 McpServer 为请求租约池，画布为共享单通道，业务模式若存在全局或 server 实例上会串会话。

证据与完整设计见 [Code 模式方案](../code-mode-design.md)。方案区分已实现源码与拟新增接口，不把 full/compact 目录档位当产品模式。

## 候选与排除

| 候选 | 结论 | 理由 |
| --- | --- | --- |
| 声明表 + 纯函数配置解析 + 显式请求上下文 | 推荐 | 变化主要是技能/上下文/UI 元数据；足够覆盖两个子模式与扩展要求 |
| Strategy/Abstract Factory 类体系 | 排除 | 尚无独立执行算法或成套产品族，配置与组合足够 |
| 按前后端复制一套 MCP server 和会话类型 | 排除 | 重复目录、权限与持久化，扩大兼容面 |
| 首版内置完整聊天、编辑器和终端 | 暂不采用 | 当前无 agent runtime，需新增沙箱和进程生命周期，超出轻量模式扩展 |

## 结论

不引入设计模式框架，保持声明表、函数与现有注册方式。mode 为会话级 design/code，submode 为 code 下的稳定字符串 ID，toolProfile 与 platform 独立。首版外部宿主执行代码；本项目提供可选会话控制、Handoff、技能路由与结果摘要。

此为提议，完整工作台、宿主集成范围与技术栈仍待产品确认。

## 实施方案

- shared 新增模式/子模式声明与 Zod 契约；静态字典统一放 shared/dicts。
- ui 复用 Shell、日志、toast、i18n，新增模式/子模式/会话/工作区摘要；业务 store 不混入连接状态。
- daemon 在池外保存 WorkSession/WorkRun 元数据；begin_run 冻结配置；现有工具注册入口扩展请求上下文，batch 继承同一上下文。
- MCP 目录按启动配置固定，不随 mode 切换增删。代码工具由宿主管理权限，新增控制面须先完成配对与会话所有权校验。
- skills 保留 canvas，新增 code-common、code-frontend、code-backend；扩展固定复制脚本与 manifest 校验，增加同源普通资源回退。
- 本次不实现产品功能、执行器、完整工作台、多画布路由、多仓库或自动全栈编排。

## 成本与退出条件

新增会话绑定、元数据存储、宿主适配和技能发布维护成本；未集成宿主只能复制任务包，不能承诺实时状态或权限强隔离。

若确认仅需设计稿转代码，收窄后端与运行模型。若必须内置执行器，另作 runtime/沙箱设计。回退关闭 code 启动开关并重新协商目录，旧设计功能保持，新会话元数据独立保留。
