# 9c4b0406. MCP代理保留协议元数据与补全：目录同步和进程生命周期分离

- **日期：** 2026-11-01
- **状态：** 已采纳
- **影响范围：** mcp-server/daemon、mcp-server/__tests__
- **相关记录：** 0006（目录体积投影）、0030（服务装配与生命周期）

## 压力

daemon 已注册图标、参数补全与资源缓存，但 proxy 手工重建目录时丢了 icons、_meta、annotations 和 completion 请求入口。此前只能检查 daemon 的目录，覆盖不到宿主实际收到的接口。

现代 HTTP 上游必须打开 subscriptions/listen 才能收到目录变更。仅注册通知 handler 并不建立订阅。旧代理还在传输错误后无条件重放 tools/call，创建类操作可能重复执行。

## 候选与排除

| 候选 | 结论 | 排除理由 |
|---|---|---|
| 保留 SDK 注册与 schema 投影，拆出目录适配函数 | 采用 | 维持现有目录预算、校验与双 era 兼容，并能单独验证两跳链路 |
| 全量替换为裸 JSON-RPC 透明代理 | 排除 | 需要重新承担协议转换、能力协商、目录预算与取消语义，超出本次缺口 |
| 在 daemon 和 proxy 各维护一套候选、图标与缓存表 | 排除 | 重复事实继续漂移，缓存结果原本已能直接透传 |

## 结论

不引入新的模式框架。保持现有代理，用局部函数分开协议适配与进程恢复；能力来源仍唯一归 daemon。

## 实施方案

- catalog-proxy.ts 持有 McpServer、目录注册表与同步队列；proxy.ts 只处理 stdio、探测、重连与订阅生命周期。
- 工具、prompt、资源和模板镜像保留 icons 与 _meta；资源保留 annotations。工具图标加入 diff 指纹与体积读数。
- completion/complete 按上游能力注册并转发，候选与上下文由 daemon 处理，不复制补全表。
- 请求透传取消信号及业务 _meta；进度映射回宿主 token；代理等待预算覆盖 120 秒批次。
- 目录重新同步强制刷新上游缓存；资源读取绕过代理客户端缓存，保留上游响应的 ttlMs/cacheScope，让宿主自行决定缓存。
- 每类目录同步串行化，避免定时同步、通知和重连同时改同一注册表；失败不毒化后续队列。
- 现代上游显式订阅目录变更；订阅远端关闭后恢复连接并重新订阅，旧连接关闭回调不得影响新连接。
- stdio 输入结束时关闭上游客户端与订阅，避免新增的长连接让 proxy 残留；不关闭共享 daemon。
- 通知保留业务 _meta 与扩展参数，移除上游连接的订阅、协议版本与服务身份字段，由下游 SDK 重建信封。
- 工具仅在 readOnlyHint 或 idempotentHint 为 true 时允许传输错误后重放；其他工具恢复连接后返回原错误，执行结果不确定时不自动再写。
- 重连完成后异步排入目录同步，不能等待可能正卡在重连上的同步队列。
- 本次不新增 OAuth、Tasks、Sampling、资源变更生产器或双向业务流程；当前没有对应使用场景。现有 skills 转发继续复用同一上游连接恢复出口。

## 成本与退出条件

- 成本：两个小模块、每类目录一条串行队列、每个 proxy 一条现代目录订阅；无新依赖、无额外业务网络跳数。
- 同步与通知可能同时产生失效通知；通知只表示缓存失效，不代表业务事件执行次数。
- 能力声明在下游握手前确定；上游重启新增能力后，宿主需重连以重新协商。
- 若 SDK 提供兼顾 schema 投影与双 era 的完整 gateway，替换 catalog-proxy，保留两跳集成用例；不再逐项维护代理字段。
