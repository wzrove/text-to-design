# 0023. 组件属性读形态与写形态之间要有单点映射，套用覆盖不再隐式换变体

- 状态：已采纳（Figma 真机复验见文末）
- 日期：2026-09-24
- 关联：0007（不许「回显成功实则没生效」）、0011（异步取 mainComponent）、0016（文案与代码同源）、0019（MG 组件属性管理）、0022（判定归位 core）
- 台账指纹：`b4e3e86aa485` `2d5b48bd627b` `f433951f1b38` `796c84f3a501`（同一根因的四个出口）

## 压力

2026-09-24 Figma 组件族冒烟（用例 `case-20260924-0002`）里，四个入口被引擎逐字相同地拒绝：

```
in setProperties: Property "setProperties.properties" failed validation:
  Expected .Property 1 to be one of the following, but none matched:
    Expected boolean, received object / Expected string, received object
    Required value missing at .Property 1.id
    Invalid literal value, expected "VARIABLE_ALIAS" at .Property 1.type
    Unrecognized key(s) in object: 'value'
```

- 出口：`jsd_set_instance_properties`、`jsd_apply_overrides`、`jsd_sync_overrides`、`jsd_platform_op(figma_component_properties_set)`。
- 事实：Figma 的写侧签名是 `setProperties(properties: { [propertyName: string]: string | boolean | VariableAlias })`（`@figma/plugin-typings` 1.137.0 `plugin-api.d.ts:11115`），而 `{type, value}` 是 `componentProperties` 的**读形态**（同文件 9573-9589 的示例：读出来带 `type`，写进去只给值）。本仓把读形态原样回喂写侧。
- 更难堪的一点：`jsd_set_instance_properties` 的 inputSchema **自己承诺**「需要显式类型时传 `{"type":"INSTANCE_SWAP","value":"1:2"}`」—— 调用方照文档传就一定被引擎拒。所以这不是「用错了参数」，是契约与现实不一致。

第二条压力来自修它的后果：覆盖快照里带着源实例的 `variantProperties` 与 VARIANT 型组件属性，套用时写它们＝**改目标实例的变体身份**（隐式换绑）。而 `swapToSource` 默认 `false`，其描述写着「swap 会丢失目标既有覆盖，需显式开启」。今天这条语义没爆，纯粹因为形态先崩了 —— **只把形态修对，就会把一次响亮报错换成一次静默换绑**，正是 0007 要根除的形状。所以两件事必须一起定，不能只修一半。

## 候选与排除

1. **四个调用点各写一遍 `v.value`** —— 排除。同一份形态知识抄四遍，`ui/src/code/figma/ops.ts` 那份还会随 typings 漂移；0022 刚把「平台事实只写一处」立成规矩。
2. **快照里干脆不采 `componentProperties`** —— 排除。布尔/文本/换绑覆盖正是这套工具的价值所在，砍掉等于把 `apply_overrides` 退化成只能改样式。
3. **在 schema 层禁止 `{type,value}` 形态** —— 排除。`INSTANCE_SWAP` 与 `BOOLEAN` 在同名候选下确实需要显式类型来消歧；问题从来不是「调用方给了类型」，是我们没把类型翻译成引擎要的写法。
4. **采用**：shared 里一个纯函数承担「读形态 → 写形态」的唯一映射（含 `SLOT` 跳过，引擎明确 `cannotSetSlotProperty`），四个出口共用；变体身份改由 `swapToSource` 显式决定，`false` 时跳过并走 `warnings` 点名。

## 结论

- 形态映射是**单点纯函数**，放 `shared/src/core/component.ts`（与它唯一的消费方同处，不新开模块）：值形态原样通过，`{type,value}` 取 `value`，`SLOT` 跳过并回报跳过的键名。
- 「套用时换不换变体」是**语义口径**，不属于映射函数：`applyOverrideSnapshot` 在 `swapToSource === false` 时既不写 `variantProperties` 也不写 VARIANT 型属性，并把跳过的项写进结果 `warnings`；要换变体请显式 `swapToSource: true` 或用 `jsd_swap_component`。
- 出参因此需要一个 `warnings` 出口（`manageComponentsResultSchema` 原先没有）—— 与 `updatedResultSchema` 的既有字段同名同形，不新造概念。

## 最小落地

1. `component.ts` 新增导出 `toComponentPropertyWrites(props)` → `{ writes, skipped }`；
2. `setInstanceProperties`、`applyOverrideSnapshot`（apply/sync 共用）、`ui/src/code/figma/ops.ts` 的 `setComponentProperties` 三处改用它，不再手搭 `{type, value}`；
3. `applyOverrideSnapshot` 增 `swapToSource` 分支：false 时滤掉变体身份，跳过的键进 `warnings`；
4. `manageComponentsResultSchema` 加 `warnings?: string[]`；
5. 单测：`{type,value}` 与裸值两种入参都产出裸值；`SLOT` 被跳过并点名；`swapToSource:false` 不改变体身份。

## 成本与退出条件

- 成本：多一个导出函数与一条 `swapToSource` 分支；`apply_overrides` 在默认参数下少写一类属性（换来的是不静默换绑 + 明确告警）。
- 退出条件：若 Figma 哪天让 `setProperties` 接受 `{type,value}`（读写字形一致），映射函数退化成恒等 —— 那时删掉它，并把工具描述里「传 `{type,value}` 会怎样」的说明一起收掉。判据是引擎不再报 `Unrecognized key(s) in object: 'value'`，需真机复验。
