# 0031. MCP 声明面照 2026-07-28 补齐：目录缓存提示 + 工具注解四 hint 必填

- **日期：** 2026-09-29
- **状态：** 已采纳
- **影响范围：** `mcp-server/`（`config.ts` 新增 `CATALOG_TTL_MS`、`server.ts` 与 `daemon/proxy.ts`
  的 `cacheHints`、`core/registry.ts` 的 `ToolHints` 由四个可选字段改为**全部必填**、
  `tools/*.ts` 全部 53 个工具的注解补全、`tools/{nodes,components,update-common,create}.ts` 的
  局部 def 类型随之收紧）
- **相关记录：** 0006（目录体积 —— 目录是「模型看不看得见工具」的事实）、0016（工具面文案的装配期投影）
- **取代：** 无

## 压力

MCP 2026-07-28 把两件事变成**服务端必须如实声明**的字段，而这两处的缺省值都不站在本项目这边：

1. **结果缓存（SEP-2549）**：`tools/list` / `prompts/list` / `resources/list` /
   `resources/templates/list` / `resources/read` 的结果必须带 `ttlMs` 与 `cacheScope`。
   SDK 在不配置时的行为是 `ttlMs: 0` / `cacheScope: 'private'` —— 语义上「一律不许缓存」。
   对本项目这是**双向损失**：目录（约 1.3 MB，同一 daemon 版本下恒定）白被重拉；
   而画布类资源又必须保持「不缓存」，得显式钉死，不能靠运气落在缺省值上。
2. **工具注解（`ToolAnnotations`）**：四个 hint 都带缺省值 —— `readOnlyHint=false`、
   `destructiveHint=true`、`idempotentHint=false`、`openWorldHint=true`。也就是说**不声明**
   等于告诉客户端「这个工具会改数据、不可重试、还要联网」。改造前：`idempotentHint`
   在全部 53 个工具里**一次都没有出现过**（`core/registry.ts` 声明了字段，没人写值），
   `jsd_platform_op` 还把 `openWorldHint` 标成 `true`（它只改当前文档的变量/样式表，不发网络请求）。
   后果由客户端决定：保守客户端会把 11 个幂等 setter 当破坏性操作、把平台门控当作要联网而弹确认。

两处都是「对外声明面」的同一类问题：**协议给的缺省值不是我们要的语义，而缺省是隐式的**。

## 候选与排除

| 候选 | 结论 | 排除理由 |
|---|---|---|
| 显式声明：目录类给 TTL，画布类钉 0；注解四 hint 全部必填，由类型守住 | 采用 | — |
| 注解保持可选，只在使用处补值 | 排除 | 「忘写」是一种缺陷形态，而缺省值在语义上是**反向**的 —— 漏一个 setter 就等于对外声明它会破坏数据。必填把这一类漏写变成编译错误 |
| 逐个资源挂 `cacheHint`（`registerResource(..., { cacheHint })`） | 排除 | 六个资源的 `resources/read` 语义一致（都来自画布实时读取），按操作声明一处即可；逐资源声明＝同一事实六份 |
| 让客户端/宿主自己按语义判断，服务端不声明 | 排除 | 注解与 TTL 是服务端唯一的表达渠道，客户端拿不到画布语义 |
| 保持简单（什么都不声明，吃缺省值） | 排除 | 缺省值把「静态目录」和「幂等写」两类事实都描述反了，成本是每次重拉 1.3 MB 目录 + 客户端的误判 |

## 结论

**不引入模式**：把两份声明面照协议补齐 —— 缓存提示按「目录静态 / 画布实时」二分，
工具注解四 hint 改为必填并由类型系统守。

## 实施方案

- **目标形状（全量）**：
  - `config.ts`：`CATALOG_TTL_MS = 300_000`（目录类结果的 TTL；与目录「同一 daemon 版本下恒定」
    这一事实同源）。
  - `server.ts`（daemon）：`cacheHints` 给 `tools/list` / `prompts/list` / `resources/list` /
    `resources/templates/list` 用 `CATALOG_TTL_MS` + `private`；`resources/read` 恒 `0`。
  - `daemon/proxy.ts`（shim）：五个操作**全部 `0`** —— shim 的目录是上游镜像、会增删注册
    （`syncTools` / `syncPrompts` / `syncResources`），变化靠 register/remove 自带的
    `list_changed` 表达，**不能**让下游按 TTL 拿住旧目录。两侧取值相反是有意的。
  - `core/registry.ts`：`ToolHints` 四个字段改为必填，`BridgeToolDef.annotations` 随之必填；
    `tools/*.ts` 侧三处局部 def 类型（`NodeOpDef` / `ComponentOpDef` / `PropToolDef`）同步收紧。
  - `tools/*.ts`：53 个工具逐个写全四 hint，取值按语义分四类 ——
    只读（`jsd_ping` / `jsd_get_selection` / `jsd_find` / `jsd_list_fonts` / `jsd_copy_overrides`）、
    幂等写（11 个 `jsd_set_*` + `jsd_move_node` 等 + `jsd_fill_image` + `jsd_apply/sync_overrides` +
    `jsd_reparent_nodes` + `jsd_select_nodes`）、新增类写（各 `jsd_create_*` / `jsd_clone_node` /
    `jsd_group_nodes` / `jsd_html_to_design`）、破坏性（`jsd_delete_node` / `jsd_flatten_nodes` /
    `jsd_outline_stroke` / `jsd_repair_nodes` / `jsd_swap_component` / `jsd_detach_instance` /
    `jsd_combine_as_variants` / 两个 `jsd_manage_*` / `jsd_batch`）。
    `openWorldHint` 只有 `jsd_import_component`（真读团队库、受权限/网络影响）为 `true`。
  - 10 个 per-type create 的四 hint 写在 `createNodeTool` 一处（同一事实不抄十份）。
- **本次不做**：
  - 不给 `resources/read` 之外的资源按平台/资源细分 TTL：没有差异证据。
  - 不改 `destructiveHint` 的既有取值（未在本次审查范围内的工具，其破坏性语义保持原判，
    例如 `jsd_ungroup_nodes` 仍为 `false`）—— 只补齐缺失的两个 hint。

## 成本与退出条件

- 成本：53 个工具的注解从「可选」变「必填」，新增工具时必须写四行；类型收紧会让
  漏写立刻变成编译错误（这是目的，不是副作用）。
- 退出条件：若将来目录不再是静态的（出现按连接/按用户条件注册的工具），
  daemon 侧 `tools/list` 的 `CATALOG_TTL_MS` 必须回到 0 —— 那时「目录静态」的假设失效，
  与 0030 的实例复用一起重新评估。

## 验证

- 不变量测试：`packages/mcp-server/src/__tests__/` 24 例通过（含 `catalog-budget` 6 例 ——
  注解不参与目录体积口径，确认没有把目录撑大）。
- 边界/并发/重试用例：真实 HTTP 往返逐条读回 53 个工具的注解，断言四个 hint **全部**是布尔值
  （53/53 齐备）；`tools/list` 原始报文断言 `resultType=complete, ttlMs=300000,
  cacheScope=private`；daemon 单例下 `tools/call` 5.0 ms、`tools/list` 3.7 ms。
- 指标与日志：无新增日志；`pnpm typecheck` 通过（43 个工具定义的必填注解由编译器守）。
