# 0018 实例变体写入:MG 上改为「集合内换绑 + 回读校验」

- 状态:已采纳（代码已落地并通过类型检查/不变式测试/构建；**真机复验已通过**，见下）
- 日期:2026-09-24
- 相关:[0017](0017-第三平台MasterGo接入：门面投影加契约两处异步化.md)（第三平台接入）、0010（契约纪律）、0007（不允许静默失效）

## 压力

`jsd_set_instance_properties` 在 MasterGo 上**回包成功、画布不变**：

1. 传变体属性名 `{"属性 1":"备选"}` → 回读 `variantProperties` 仍是 `默认`，不报错；
2. typings 声明的两条入口都试过：
   - `InstanceNode.setProperties({[propertyId]: string|boolean})`（`@mastergo/plugin-typings` 3097 行）；
   - `InstanceNode.setVariantPropertyValues(Record<string,string>)`（3094 行，`ComponentNode` 3057 行也有）；
3. 按 propertyId 写的路子**根本走不通**：`ComponentProperties.id` 在 typings 里是可选（3023 行），
   真机上**实例侧**的项没有该字段（只有 `name/type/value/…`）。
   **收窄(0019 复验更正)**：`id` 只在**组件侧**有 —— `componentPropertyValues` 的项同时带
   `name`（`显示图标`）与 `id`（`20:395`），别一概而论成「MG 不给 id」。

即：typings 有声明、运行时不生效 —— 属于「静默失效」家族（0007 明令不允许），
且它是 `setProperties` 的**唯一**变体写入入口，所以修法必然新增分支/抽象，跨 `ui/` 多文件。

## 证据（真机 2026-09-24，第三平台 MasterGo 桌面端，daemon 为本仓 0.8.2）

| 尝试 | 结果 |
|---|---|
| `jsd_set_instance_properties {属性 1: 备选}` | 回包 `updated:[…]`，回读 `variantProperties={"属性 1":"默认"}`、宽不变 —— **静默无效果** |
| 同上，换 propertyId 形态的键 | 无 id 可取（`componentProperties[].id` 运行时不存在）→ 与上面同形 |
| `jsd_swap_component {ids:[实例], componentId: 目标成分}` | ✅ 回读 `variantProperties={"属性 1":"备选"}` —— **唯一有效路径** |
| 造第二个变体值的手段：`jsd_rename_node` 成分改名为 `属性 1=备选` | ✅ MG 归一成 `属性 1[a1]=备选`，`variantProperties` 随之为 `备选`（联调用法，值由**名字**驱动） |
| 合并成集合时两个成分的值 | 都是 `默认`（`属性 1[a0]=默认`）—— 同一个集合里若没有第二个值，本项**无法实测** |

## 候选与排除

| 候选 | 排除理由 |
|---|---|
| 只调 `setVariantPropertyValues` | 真机静默无效；且我们无法判断「宿主没实现」还是「参数形态不对」，赌它会写成赌注 |
| 按 propertyId 调 `setProperties` | 运行时拿不到 id，形态上就不可能 |
| 只在文档/描述里点名「MG 切不了变体」 | 变体切换是组件工作流的核心动作，直接宣布不支持太亏；且 swap 这条真机有效 |
| **集合内换绑 + 回读校验**（采纳） | 真机验证有效；换绑后回读可判定，不需要猜宿主实现 |

## 结论

1. **变体写入 = 集合内换绑**：取当前 `variantProperties` 与请求合并（部分更新语义），在同一
   `COMPONENT_SET` 的成分里找**变体值全等**的那个，`swapComponent` 过去。
2. **全等匹配，不是包含**：变体维度是笛卡尔积，部分匹配会挑错组合（`{尺寸:a1,状态:禁用}` 也「包含」`尺寸=a1`）。
3. **匹配不到就抛错**：错误里列出集合里的可用组合，并提示回读 `variantProperties` 的全部取值 ——
   绝不放行（原生入口的坑正在于「成功但没变」）。
4. **回读校验**：换绑后重读 `variantProperties` 与期望值比对，不一致即抛错（宿主行为再变会当场暴露）。
5. **拆分判据按属性类型，不按值类型**：`TEXT` 组件属性的值同样是字符串，只按「是字符串就当变体值」
   会把文案属性错送进换绑路径。类型的真源是节点自己的 `componentProperties`（MG 给 `type`），
   名字的真源是 `variantProperties`；两者都没有时按「字符串兜底算变体值」。
   归到变体但值不是字符串的键**明确报错**（`wrongType`），不静默丢。
6. **纯函数化**：拆参数/合并期望值/选成分落在 `ui/src/code/mastergo/variant-swap.ts`，可单测；
   宿主调用（`mg.getNodeById` / `swapComponent`）留在 `node-facade.ts` 的薄胶水里。
7. typings 的两条入口断言**保留**（`sync-guarantee.ts`）：它们守的是「typings 里确实有」，
   官方改动时提醒回来复核；注释里写明运行时行为与本文结论。

## 真机复验（2026-09-24，插件重载后）

| 步骤 | 结果 |
|---|---|
| 造两值变体集（合并后把第二个成分改名为 `属性 1=备选`，MG 归一成 `属性 1[a1]=备选`） | ✅ `variantProperties` 分别是 `默认` / `备选`；集合 children 仍是原组件 id（原位） |
| 实例起点 | `{"属性 1":"默认"}` |
| `jsd_set_instance_properties {属性 1: 备选}` | ✅ 回读 **`{"属性 1":"备选"}`** —— 换绑路径生效（旧实现此处是「回包成功、画布不变」） |
| 回切到 `默认` | ✅ 再回读 `{"属性 1":"默认"}` |
| 错误路径：请求集合里没有的值 | ✅ 明确报错：`无法切变体:集合里没有变体值匹配 属性 1=不存在的值 的成分。可用组合:属性 1=默认 \| 属性 1=备选。可先用 jsd_find 看 variantProperties 的全部取值。`（不是静默放行） |
| `jsd_sync_overrides`（core 的组件属性补丁 → `setProperties`） | ✅ 源实例 `备选` → 目标实例从 `默认` 同步为 `备选`，`applied[0].ok=true` |
| 画布 | 全部测试节点逐个删净（复查 COMPONENT_SET / INSTANCE / COMPONENT / RECTANGLE 均为空） |

**副产物（联调用法，值得记）**：MG 的变体值由**成分名字**驱动 —— 把集合里的成分重命名为
`属性 1=备选`，MG 会归一成 `属性 1[a1]=备选` 并把该成分的 `variantProperties` 置为 `备选`。
工具面没有 `createVariantProperties` / `editVariantPropertyValues` 的入口，这是目前**唯一**
能在真机上造出第二个变体值的手段（本轮实验即靠它）。
