# 0036. 删掉内置图表编译器：图表一律走代码生成 SVG 再导入配方

- **日期：** 2026-10-09
- **状态：** 已采纳
- **影响范围：** `shared/`（删 `schemas/chart.ts`、删 `dicts/chart.ts`、`{schemas,dicts}/index.ts` 各摘一条出口、i18n 少一键 `createChart.title`）；`mcp-server/`（删 `src/charts.ts`、`tools/chart.ts`、`tools/index.ts` 的注册、`__tests__/chart.test.ts`、`smoke-chart.ts`；重写 `tools/prompts.ts` 的 `chart-by-code` 配方与 `tools/create.ts` 的 `jsd_create_svg` 描述；新增 `__tests__/chart-prompt.test.ts`）；两个 `README.md` 的工具表；**不改**插件侧（`ui/`）、不改线格式（`PluginMethod` / `createSvgSchema`）、不改 core 写管线
- **相关记录：** 取代 0035；沿用其「复用 `execute`/`create_svg` 两条既有写通道、不新增插件方法」与「读本地文件与 `jsd_fill_image.sourcePath` 同构」；目录体积口径沿 0006、不按平台重定义工具沿 0020、静默失效出口沿 0007、i18n 键化沿 0016

## 压力

1. **口径变更，且被拿走的是 0035 的主路径。** 0035 落地的是「内置编译器优先（默认）、代码配方兜底」的两条路径（工具数 +1 = `jsd_create_chart`）。新要求是**只保留提示词**：图表一律由调用方自己写代码算几何、导出 SVG、经 `jsd_create_svg` 导入。故这不是「再加一条」，而是「删一整套」。
2. **维护面成本是可量化的。** 只服务四种图（bar/line/area/pie）的东西有：`src/charts.ts` 540 行纯函数编译器、`schemas/chart.ts` 150 行声明式校验、`dicts/chart.ts` 全表、`__tests__/chart.test.ts` 546 行不变式、`smoke-chart.ts` 目视预览脚本。0035 的「退出条件 ③」已经写明「若第二路径实测稳定性达标，砍掉配方只留编译器」——反向同样成立：**砍编译器只留配方，不占线格式、不占依赖、没有兼容包袱**。
3. **两条路径并存还额外背着一层一致性约束。** 为了让两条路「出的图像同一个人做的」，配方被迫从 dict 读配色/文字色/尺寸，0035 还专写了一节「与内置图表保持一致」。删掉一条，这层对齐约束（以及它带来的同步维护）自然消失 —— 其后连这份 dict 本身也被判定为多余的「第二套设计体系」（见变更历史）。
4. **能力缺口不因删除而扩大。** 种类覆盖面本来就不由编译器决定（四种是它的上限，配方是无上限）；删掉编译器后覆盖面不变，只是几何的计算位置从服务端挪到调用方。

## 候选与排除

| 候选 | 结论 | 排除理由 |
|---|---|---|
| 删掉编译器与 `jsd_create_chart`，只留 `chart-by-code` 配方 + `jsd_create_svg` 的 `svgPath` | **采用** | 覆盖面不设上限（雷达/热力/桑基/瀑布…），执行面**不新增**：算几何用的是调用方自己已有的执行环境，本仓不引任何图形库、不开「执行外部代码」这个新信任边界 |
| 保留编译器，只把配方里的「优先用内置」改成「可选」 | 排除 | 与用户口径不符（要求是删实现）；留着就是 540 行只服务四种图，且几何来源长期两份 |
| 反向：删配方、只留编译器 | 排除 | 覆盖面直接封顶四种；与本次要求相反 |
| 在 daemon 里起 JS 沙箱（`node:vm`）跑调用方给的绘图代码 | 排除 | 0035 已排除且理由不变：收益被「调用方本就能执行代码」抵消，代价是本项目第一个「执行外部代码」的能力（超时/死循环/内存/依赖解析都要自己兜，`vm` 又不是安全边界） |
| 插件侧新增图表节点类型或 op | 排除 | 三平台引擎都没有统一的「图表节点」概念（0020 已否掉「按平台重定义工具」），且它不解决表达力问题 |

命中「停止条件」：只剩**一条**实现路径、变化无证据、语言原生能力（调用方的 node + 一次 `create_svg`）足够。

## 结论

**不引入模式，且不保留内置编译器。** 图表能力收敛为「一份配方 prompt + 一条既有写通道」：

- `chart-by-code` 配方（`mcp-server/src/tools/prompts.ts`）——**唯一入口**：三步（自己写脚本算几何并落盘 → 确认文件非空 → `jsd_create_svg({svgPath})`）+ `jsd_export` 目视验收；写明与库无关的坑（无 DOM、全程自算坐标、输出固定）、引擎侧的硬约束、以及配色/字号「指向画布既有样式与变量」的读法。**不点名任何图形库**：指名就把模型绑到一个包上，也让「换个库」变成改文档。**也不自带色板**：本仓不再持有任何图表配色/尺寸字典（见变更历史）。
- `jsd_create_svg` 的 `svgPath` 来源（0035 已落地，本次**保留**）——服务端 `readFileSync` 读盘，几十 KB 的 SVG 不进工具入参。
- `dicts/chart.ts` **整个删掉**（后续变更：见变更历史）。配色与字号不再由本仓给：配方改成「**先读画布上已有的样式/变量**（资源 `jsd://styles`、相邻节点的 `boundVariables`、`jsd_ping` 的变量面）照抄，读不到才回退手写 hex」。图的皮跟文档走，不跟本仓走 —— 一份内置色板只会跟用户的真实设计体系打架。

**已知代价（要写进配方的诚实交代）**：文字这次必须进 SVG —— 没有原生骨架那一半了。故配方明确要求显式写 `font-family`/`font-size`，并声明字体不保证按写的走。不再假装同时拿到「几何保真」与「字体可控」。

## 实施方案

- **角色与职责**：本次没有新增角色。配方是静态引导词（不依赖插件连接，恒可用）；落盘与算几何都在调用方；`jsd_create_svg` 只多认一个 `svgPath` 来源。
- **接口所在层与依赖方向**：不变 —— `mcp-server → shared`；插件线格式（`PluginMethod` / `createSvgSchema`）仍要求 `svg` 必填，来源之争在 MCP 侧的 `createSvgInputSchema` 解完，插件不需要具备读盘能力。不进 `core`、不碰 `DesignHost` 契约。
- **一次调用的时序**：调用方脚本 → 本地 `.svg` → `jsd_create_svg` → 一次 `create_svg` 桥往返 → `jsd_export` 目视验收。比 0035 的四次往返少了三次（execute / reparent / move），但画布上是一个整体 SVG 图层，没有可单独编辑的标题/图例文本。
- **删除清单**：`mcp-server/src/charts.ts`、`mcp-server/src/tools/chart.ts`、`mcp-server/src/__tests__/chart.test.ts`、`mcp-server/smoke-chart.ts`、`shared/src/schemas/chart.ts`、`shared/src/dicts/chart.ts`；`shared/src/{schemas,dicts}/index.ts` 的出口、`mcp-server/src/tools/index.ts` 的注册、两语 i18n 的 `createChart.title`。
- **保留清单**：`jsd_create_svg` 的 `svgPath` + `MAX_SVG_SOURCE_BYTES` 护栏 + `create-svg-source.test.ts`；`chart-by-code` 配方及其注册测试（从 `chart.test.ts` 迁出为 `chart-prompt.test.ts`）。
- **没有执行环境时怎么办**：配方里给明确替代路径 —— 改用原生图元（FRAME/RECTANGLE/TEXT）摆近似图，或让调用方换一个有 shell 的宿主；**不**退回「手算坐标硬拼 SVG 再内联进 `svg` 入参」（几十 KB 塞进入参既费上下文又易在转义上翻车，这正是开 `svgPath` 的原因）。
- **本次不做**：在 daemon 里执行调用方给的 JS、图表主题/暗色皮肤、图例点击联动、坐标轴对数刻度、把图表封装成 COMPONENT、恢复任何内置图种。

## 成本与退出条件

- 成本：**净删除** —— 约 1.4 k 行代码 + 1 个测试文件 + 1 个预览脚本 + 1 条目录体积条目 + 1 个 i18n 键。代价在能力面：没有可执行环境的宿主演不出图；几何由调用方算 ⇒ 一次一个样、不可单测。
- 退出条件：若「模型自己写的绘图代码」实测稳定性远低于预期（大量空图/越界），**且**「无执行环境的宿主」成为真实场景，就恢复 0035 的内置编译器（`jsd_create_chart`）。恢复不需要改任何接口签名：把删掉的那套加回来即可，`shared` 的 spec schema 与字典也按 0035 原文重建。

## 验证

- 不变量测试（`packages/mcp-server/src/__tests__/chart-prompt.test.ts`，起真实 server + in-memory 客户端读配方正文）：① 配方能取到，标题/正文都不是裸 i18n 键；② 需求参数真的进正文；③ 正文**不点名任何具体图形库**、也不含让模型去装包的命令（`npm i` / `npx`）；④ 正文含 `jsd_create_svg` + `svgPath` + 缺省落盘路径 + 零依赖示例；⑤ 配色/字号指向**画布既有样式与变量**（`jsd://styles`、`boundVariables`、`jsd_ping`），手写 hex 只作兜底；⑥ 正文里不残留未插值的 `${`；⑦ 正文里**不再出现** `jsd_create_chart`；⑧ 写明「没有执行环境时怎么办」，不留死路。
- 回归门禁：`pnpm typecheck`、`pnpm vitest run`（i18n 键集一致性测试会守住两语同步删键；目录体积测试会看到工具数 −1）、`pnpm build`。改 `mcp-server/` 后需**重启常驻 daemon** 才验证得到新产物。
- 需真机验证（沿 0035 的待验项，本次未验）：三平台 SVG 导入对 `path`（含 `C` 曲线）、`circle`、`fill-opacity` 的保真差异；`<text>` 未按写的字体走时的实际回落。**0035 的另两项待验随骨架一起删了**（reparent 后 `move` 的落位、导入图层的白底）。
- 指标与日志：`svgPath` 的读失败/为空/超限文案都在结果里逐条可追（`create-svg-source.test.ts` 守着）；配方里点名「空文件是最常见的失败」，要求先确认落盘成功再导入。
