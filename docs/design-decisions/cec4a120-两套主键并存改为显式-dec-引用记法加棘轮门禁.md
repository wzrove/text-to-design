## 压力

1. **两套主键并存，但没有第二套解析入口**：`de446d4e` 只换了**取号与索引**（`--status` 认 `0007` / `0007-标题.md` / `a1b2c3d4`），代码注释层的引用格式从未被规定过。实测：包内四位号引用 247 处，短 id 引用 **1 处**（还是本批刚写的）。机制上短 id 完全可以索引（文件名一律 `标识-标题.md`，45 个记录文件里唯二例外是两个 INDEX），但它没铺开 —— 因为 `// 见 7165f370` 读不出「这是什么事」，人自然滑回熟悉的数字号。
2. **没有任何门禁校验注释里的编号指向真实记录**。唯一的程序化引用检查是 `tests/platform-knowledge.test.ts` 的证据可追溯，而它只吃事实表 `evidence` 数组里**以路径或 `@包名` 开头**的条目；普通注释里的 `(0040)` 一条都不守 ⇒ 悬空指针不会被发现。
3. **归属已经含糊，且含糊是有代价的**：`platform-knowledge.ts` 原写 `figma_variables_apply(0040 起带 unbind;此后一次吃 bindings[] 多组)` —— `unbind` 与「op 形制对齐」确属 0040，但「一次吃 `bindings[]` 多组」是 `7165f370` 做的。下一个读代码的人按 0040 去翻，翻不到多组绑定的理由。
4. **想用正则扫引用必然失败**：包内 `\b[0-9]{4}\b` 的分布 —— `2026` 97 次（日期）、`1024` 18 次（体积常量）、其余大量 typings 行号（`:1832` / `:1176`），假命中比真引用多。这正是 `de446d4e` 自己记下的「全仓 720 处数字串引用，混着年份、端口等假命中，要逐条判」。

## 候选与排除

| 候选 | 结论 | 排除理由 |
|---|---|---|
| 门禁扫「形似编号」的 token（`\b\d{4}\b` / 8 hex） | 排除 | 见压力 4：必须先消灭假命中，而「像不像编号」这个判据本身消灭不了 |
| 门禁扫「token 是否等于某个已知标识」 | 采用（作为集合判据） | 标识集合来自目录里的真实文件名，年份/行号/体积天然不在其中；一次过滤同时挡住假命中与漏判 |
| 只扫裸标识，不引入新记法 | 排除 | 「裸标识=引用」仍然有歧义（`0024` 可能是数组下标、文件名片段、颜色值 `#0024`），且改动时无法区分「这条注释在指记录」与「碰巧撞上标识形状」 |
| 注释显式写 `dec <标识>`，门禁只认标注 | 采用（主） | 判别形状自带；两种主键走同一条解析（`normalizeIdent` 先判 8 hex、再补零成四位），短 id 不是二等公民；旧注释**不追认**，用棘轮守新增 |
| 把 0001–0043 全部重写成短 id | 排除 | `de446d4e` 已排除过一次（38 个文件改名 + 720 处引用逐条判 + 外部旧引用失效），本批不重提 |
| 门禁改扫「所有 247 处裸引用」 | 排除 | 一次性改写既淹死 diff，又违反 `de446d4e` 的「旧记录正文与既有引用一字不改」；棘轮能收敛又不违反 |
| 把解析函数 import 自技能脚本 `.agents/skills/…/new_decision.mjs` | 排除 | 技能是项目无关的，仓内代码不许反向依赖它（dec 0009）；故仓内自建一份，脚本仍可各用各的 |
| 在测试里 `import` 新脚本的函数 | 排除 | 根 `tsconfig.json` 无 `allowJs`，`.mjs` 走类型检查要补 `.d.mts`；测试改为吃 CLI 的 `--json`，既避开类型摩擦又顺带验证人用的那条命令 |

## 结论

**显式引用记法 + 棘轮门禁 + 一个反查 CLI**，不引入模式、不加抽象层：

1. **记法**：注释引记录一律写 `dec <标识>`，`dec 0024` 与 `dec 25827d0c` 同等对待。归属规则写成一句：**标识 = 做出这次形状变更的那条记录，不是「相关的那条」**。
2. **门禁（只扫 `dec` 标注）**：标注必须解析得到真实记录；标识在目录内唯一（挡撞号，`de446d4e` 那个「0039 两条」的人工例外从此由工具守）；文件名必须以标识开头；每条记录至少进一个索引表（主索引或年档 —— 写完记录忘加行至今无人守）。
3. **棘轮**：裸标识引用（等于已知标识、且不带 `dec` 前缀）只许降不许增，基线 435；降了就把常量一起改小。
4. **反查**：`locate <file>` 列出这个文件牵到的记录（带状态），`resolve <标识>` 支持 `0024` / `24` / `25827d0c` / 大小写混写四种输入 —— 这是「两套主键都要支持」的落点：不是两套规则，是**一条归一函数吃两种形态**。

## 实施方案

- `scripts/decision-refs.mjs`：`identOf` / `normalizeIdent`（8 hex 优先，旧号补零，允许省略前导零）/ `buildIndex`（返回 `byIdent` + `dupes` + `unnamed`）/ `commentTextOf` / `scanRefs` / `indexCoverage` + CLI（`check [--json]` / `locate` / `resolve`）。`CODE_ROOTS` 与 `pnpm run typecheck` 覆盖范围一致。
- **踩过的坑（写进代码注释，别改回去）**：`commentTextOf` 第一版用 `^\s*\*?\s?(.*)$`，`\*?` 可选 ⇒ 整份文件都被当注释收进来了，连 `run(['resolve','0039'])` 的字符串都算引用，裸引用计数从 418 虚涨到 435。判据必须是「这行**以**注释符开头」，且块注释要跨行续读。
- `tests/decision-refs.test.ts`：`spawnSync` 调 CLI 读 `--json`（`check` 有问题时退出码 1 但仍打 stdout ⇒ 不能用 `execFileSync`，它会在非零退出时抛、拿不到 `problems`）；断言 = 体检无问题 / 两种主键都能解析 / `dec` 确实在用 / 裸引用 ≤ 基线。
- `AGENTS.md` 新增「决策记录引用」段：记法、为什么不写裸编号（带实测假命中数）、归属规则、棘轮命令、反查命令、「索引两个文件都要看」。
- 首批改写：`core/styles.ts`（`dec 25827d0c` + `dec 0007`）、`style-kind-applicability.test.ts`（`dec 25827d0c`）、`platform-knowledge.ts` 两处含糊归属（`dec 0040` 与 `dec 7165f370` 分写，并补 `figma_variables_remove`）。

## 成本与退出条件

- 成本：一个 100 余行的仓内脚本（无依赖、无新工具链）+ 一个测试文件；注释里多一个 `dec` 词；棘轮基线是个需要手动下调的常量。
- 退出条件：① 若哪天全仓裸引用清零，删掉棘轮那条断言，只留「标注必须可解析」；② 若记录主键统一到一种形态（不再并存），`normalizeIdent` 的双分支与「两种形态等价」断言一起删；③ 若 `de446d4e` 被取代（比如旧号也迁短 id），本记录的记法不变、解析器只留 hex 分支。
