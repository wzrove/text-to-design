## 压力

1. **四类资源的关系此前只有散文，没有事实**：同一个问题（「变量、样式、组件、变体之间怎么连」）的答案在 `capability.ts` 注释、`platform-facts.ts` 的句子、`ops.ts` 的描述、配方文案里各写一份，且**已经写错**。实测错处：MG 被写成「组件属性绑不了变量」，而它的 typings 明写 `ComponentPropertyValue.variableId?`（`dist/index.d.ts:3001`，官方注释「当组件属性绑定到变量时，对应的变量 id，仅 TEXT/BOOLEAN 类型可能存在」）—— 真相是**读得到、写不了**（`setProperties` `:3097` 只收 `string|boolean`）。三家「塌缩方式」也不同向：Figma 是「变量 → 样式 → 节点」，MG 是「变量**含**样式」（`VariableType` `:1832` 后八项与 `StyleType` `:1810` 逐字重名，`type Style` `:2079` 联合里直接混着 `Variable`），jsDesign 只有样式一层。
2. **三处读侧漏字段，全是「引擎有、投影丢」**：① Figma 的 `ComponentPropertyType` 有五项（`plugin-api.d.ts:10985`，含 `SLOT`），线格式枚举只四项 ⇒ 带插槽的实例读回来过不了输出校验（`mcp-server/core/response.ts:149` 的 `safeParse`），整条 `componentProperties` 打成错误；写侧 `core/component.ts:154` 早就在处理 `SLOT` 了，两头不一致。② MG 的 `variableId` 被 `property-values.ts` 的注释当成「MG 专有字段」顺带丢掉。③ Figma 的样式级绑定（`PaintStyle` / `TextStyle` / `EffectStyle` / `GridStyle` 的 `boundVariables`，`:12432/:12496/:12521/:12537`）整条链在画布上没有出口：`assets.styles` 只给 id + 名称（`StyleSummary`），节点上的 `boundVariables` 又不含样式内部的绑定。
3. **MG 的样式面比它自己窄一半**：契约 `STYLE_KINDS` 四项，MG `StyleType` 八项，四个专属工厂 `createCornerRadiusStyle / createPaddingStyle / createSpacingStyle / createStrokeWidthStyle`（`:1459-1468`）同形（都收 `CreateStyleConfig{name, id, description?}`，`:3186`）。后果是「间距 / 圆角 / 描边宽度这套固定视觉」在 MG 上只能建成**复合样式变量**（`mg_variables_create` 的 type），于是同一件事住在两套词汇里、进两份不同的清单（`assets.variables` 而非 `assets.styles`），而删除还要分入口 —— 真机 2026-10-14 拿变量 id `3:7` 调 `jsd_delete_style`，回包 `removed`、那个变量真没了。
4. **LLM 拿不到「选哪一类」的判断依据**：`design-strategy` 第 0 条只有「每一类的复用入口」，没有「它们之间的连线」。三家连线方向不同 ⇒ 在 Figma 养成的习惯会被搬到 MG 去找「样式的变量绑定」、搬到即时设计去找变量 op；典型代价是一趟往返 + 一个「回包成功、画布没变」的假信号（0007 要根除的形态）。

## 候选与排除

| 候选 | 结论 | 排除理由 |
|---|---|---|
| 给事实表加第四个域 `styles` | 排除 | 「变量 ↔ 样式」这条关系本来就是样式域的全部差异来源，加一域等于把同一条事实抄第二遍（0029 已为此删过一份 claim 副本）；关系挂在 `variables` 域的 `nativeUnwired` / `evidence` 上，并在表头写明「样式没有独立域」 |
| 样式档读写做成新 MCP 工具（`jsd_get_style`） | 排除 | 只有 Figma 有这一档（MG 的样式没有 `boundVariables`，jsDesign 无变量）⇒ 为一个平台重定义公共工具，撞 0020；且工具目录有体积门禁（0006）。走 `jsd_platform_op` 通道，名单由 ping 的 `platformOps` 自动上报 |
| 样式级绑定做成一个 op 兼读写 | 排除 | MG 的教训就在眼前（0040：两个 op 各管各的入口），且读出口在四类上是 `readonly`、写入口只有 `TextStyle` 有 setter —— 形状不同，合一个参数面就要在 op 里搭两套分支 |
| 把 MG 那四类做成 MG 专属 op（不动契约） | 排除 | 它们**本来就是样式**，`StyleType` 里就有；另起 op 等于再造一套「样式」词汇，而 `jsd_create_style` / `jsd_delete_style` / `assets.styles` 这条通路要跟着分裂 |
| 契约加宽到八项、另两家按平台点名拒 | 采用 | 枚举是并集（三家共用一个 schema），适用性是分平台事实 ⇒ 正好落在 0022 的位置：登记表 + core 写路径判定 + `sync-guarantee` 双向断言 |
| 只补文档与策略文案、不动契约与读侧 | 排除 | ①②③ 是**能力与数据**缺口（读回来会被校验打回），不是措辞问题 |
| 顺手接上 `getStyleConsumersAsync`（谁在用这条样式） | 本次不做 | 它是独立一条链（样式 → 消费方清单），接它要先定「回包体积怎么收」（一档可能几百个节点）；已在 `nativeUnwired` 记账 |

## 结论

四件事，各自守住一条既有纪律，不引入新模式：

1. **读侧补齐（0024 / 0041 口径：按引擎词汇原样透传，不引入归一化层）**
   - `componentPropertyValueSchema.type` 加 `SLOT`（只进**读**形态：写侧 `setProperties` 对 SLOT 抛 `cannotSetSlotProperty`，`:11121`，`core/component.ts:154` 归进 skipped）。
   - 同一 schema 加 `variableId?: string`（MG `:3001` 的裸 id）。**不**并进 `boundVariables` —— MG 给的是 id 字符串而不是 `{type:'VARIABLE_ALIAS', id}`，合成一套等于替平台编形状，写后回读就没法比同一个字段。只在**组件侧**透传（实例侧 `ComponentProperties` `:3030` 没有这一项）。
2. **Figma 样式档读写两端各一个 op**：`figma_style_variables_apply`（写）/ `figma_style_variables_list`（读，含 `values` 与 `boundVariables`，空绑定不发键）。词汇与节点档**不同源**：样式上那一份填充叫 `paints`（`VariableBindablePaintStyleField`，`:6855`），子字段固定 `color`；排版档八项 = `VariableBindableTextField`（`:6845`）**且只有 `TextStyle` 有 `setBoundVariable`**（`:12507`），另三类是 `readonly boundVariables` + 三个 `setBoundVariableFor{Paint,Effect,LayoutGrid}` 返回副本再整数组赋回。表外字段当场点名拒（`fills` / `strokes` / `color` / `backgrounds` 各给原因）。apply 的回包带**写完立刻回读**的 `styles[].boundVariables` —— 这条链没有别的证据源。
3. **MG 样式面加宽到八类**：`STYLE_KINDS` 改为三家 `StyleType` 的**并集**，并派生 `COMMON_STYLE_KINDS` / `MG_ONLY_STYLE_KINDS` 两份名单（同一家平台的事实不各抄一份）。适用性登记为 `platform-value-domain.ts` 的**第五类**（`PLATFORM_STYLE_KINDS`，allow 名单形态 + `StyleKindAllowViolations`），由 `core/styles.ts` 在建样式**之前**判并点名（带「本平台只有哪四类」的可执行出口）。两侧各向断言：Figma / jsDesign 查「登记的必须真在、MG 那四类必须真不在」，MG 查「八项必须真在、宿主不得超出契约」。取值前置检查同纪律补齐（`PADDING` / `SPACING` 要自动布局容器、`CORNER_RADIUS` 要真有圆角；描边宽度与圆角族在契约里是裸 `number`，不判 MIXED）。MG adapter 的八个工厂同形，`fillStyleFromNode` 在本平台仍无调用方。
4. **关系投影给 LLM**：新增 `resourceRelationText(platform, styleEnumerated)`，与既有 `reuseGuideText`（每类的入口）分工 —— 这段专讲**连线**：三档落点与各自词汇、三套验证面、「改一次带动多大一片」的选择问句、三家一致做不到的那条（变体取值绑变量：三家变量类型表都没有 `VARIANT`）、MG 的 id 空间冲突与删除分入口、jsDesign 只有样式一层且清单恒空。接进 `design-strategy` 第 0 条与 `variable-binding` 配方；事实仍取 `platform-knowledge.ts`，本文件只拼句（0032）。

## 实施方案

- **事实表**：`dicts/platform-knowledge.ts` 的 `figma.variables` 读三条通道 / 写四个 op，`nativeUnwired` 摘掉已接的样式绑定、留 `StyleConsumers`；`mastergo.variables` 登记「变量含样式」的链路方向、词汇重名与 id 空间冲突，`mastergo.components` 更正为「读得到 `variableId`、写侧无入口」；表头写明「样式没有独立域，关系挂 `variables`」。
- **值域表**：`dicts/platform-value-domain.ts` 末尾新增第五类 + `platformStyleKindAllowed` / `platformStyleKindRejectionHint` / `StyleKindAllowViolations`；判定入口在 `shared/core/styles.ts`（`createStyle` 的能力位守卫之后、取值检查之前），与 `core/props/platform-gate.ts` 同源不同键 —— 那张表以节点字段为键，这张以契约枚举取值为键。
- **平台侧**：`ui/code/figma/ops.ts`（两张档表 + `runStyleBinding` + 两个 op 注册）、`ui/code/mastergo/{host,ops,property-values}.ts`、三侧 `sync-guarantee.ts` 断言。
- **文案**：`split-ops.ts` 的 kind describe、i18n 两侧 `createStyle.description`、`platform-facts.ts` 的 Figma / MG / jsDesign 三段关系与复用入口、`variable-binding` 配方。
- **依赖方向**：`core/styles.ts` 只认 `dicts` 的判定函数，不认识任何平台名；平台差异一律经表 + 投影点，不在 core 里 `if (platform === …)`（0022 / 0032）。
- **本次不做**：MG 四类的**枚举面**（`getLocalStrokeWidthStyles` 等 `:1517-1520`，本平台未声明 `styleEnumeration`，接了是死面）、Figma `StyleConsumers`、MG 的 mode 切换入口（`setVariableMode` / `setPageVariableMode`）、SLOT 属性的写侧支持（引擎不收）。

## 成本与退出条件

- **成本**：契约枚举 +4 项（zod 面变宽，但 `PLATFORM_STYLE_KINDS` 立刻收窄到按平台可建）；`ui/code/figma/ops.ts` 约 +330 行（两张表 + 一个 `runStyleBinding`，与既有 `runBinding` 形状对称，不共享是因为落点是 `getStyleByIdAsync` + 数组赋回）。
- **退出条件（类型层守）**：MG 的 `StyleType` 若增项，`MgStyleKindCompletenessCheck` 红 ⇒ 补 `dicts/style-kind.ts` 与 adapter 分支；Figma / jsDesign 若补上那四类工厂，`*StyleKindAbsentCheck` 红 ⇒ 从 `PLATFORM_STYLE_KINDS` 的拒绝名单里挪走；MG 若声明 `styleEnumeration`，四类 getter 才谈得上接。
- **退出条件（运行层）**：MG 的 `ComponentPropertyValue.variableId` 若哪天同时出现在实例侧（`:3030`），`property-values.ts` 的 `readComponentProperties` 要一并透传；若 MG 补上属性绑变量的写入口，第五类与 `PLATFORM_METHOD_PARAM_DOMAIN.mastergo.setProperties.deny` 一起改。
- **已知残留**：MG 建出的那四类样式**列不出来**（未声明 `styleEnumeration`），只能靠 `jsd_create_style` 回包的 id 记账 —— 这条已经写进策略文案，不是静默缺口。
