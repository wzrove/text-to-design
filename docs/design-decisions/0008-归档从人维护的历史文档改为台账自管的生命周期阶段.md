# 0008. 归档从人维护的历史文档改为台账自管的生命周期阶段

- **日期：** 2026-09-19
- **状态：** 已采纳
- **影响范围：** `.agents/skills/mcp-tdd/`（SKILL.md、references/{bookkeeping,timeline,platform-limits,workflow}.md、scripts/{mcp-tdd.mjs,buglog.sh}）、`docs/mcp-errors/`、`tests/`、`AGENTS.md`
- **相关记录：** 0005（事实一致性用 Vitest 不变式守护，不引入事件类架构）——本记录沿用同一条判据：能被机器守住的约束不靠文档纪律

## 压力

「归档」在这套技能里出现了 **5 处，指 4 件不同的事**，且只有一件真有动作：

| 出现处 | 说的其实是 | 实际状态 |
|---|---|---|
| SKILL.md 开篇「捕获 → 定位 → 修复 → 验证 → 回归 → **归档**」+ 闭环第 8 步「闭环 + 归档」 | 一次闭环的收尾 | 动作只有 `handle` + `report`，**没有任何归档动作**，名字是上一代概念的残留 |
| `references/platform-limits.md` §体积治理「滚进 `references/platform-limits-history.md`」 | 文档行数的滚动归档 | **该文件不存在**。真按它新建还会因为没写进 SKILL.md 加载路径被 `skill-doc-budget.test.ts` 的孤儿检查判红——指引本身是半截的 |
| 旧 `archive/` 目录（两份 md，含逐条根因叙述） | 上一代的**记忆体** | 2026-09-19 已删，但 **5 处文件仍在教人 `git show bd9e4da:...archive/` 取回**（bookkeeping / timeline / buglog.sh / `mcp-tdd.mjs` 的 README 模板 / `docs/mcp-errors/README.md`）——教人捞一份不存在的东西 |
| `references/timeline.md`（P1–P32） | 编号→现象字典 | 封版。**源码注释、测试名、甚至面向用户的报错文案**都在引用它（60+ 处，如 `平台缺陷 P24`），字典不能裸删 |
| 台账本身 | 报错事件流 + 闭环库 | `errors.jsonl` **只追加**，`handled.json` **只增**。README 自己写着「事件流随任务无限增长」，`list --all` 因此被迫默认截断 50 条 |

代价已经具体到可以指认：**没有任何命令能让台账变小**，所以唯一被读的清单（未决）和永不读的清单（已闭环）挤在同一个显示面上，靠 `--limit` 掩盖；同时「归档」这个词在技能里同时指代收尾动作、文档滚动、上一代记忆体三种东西，照着第 8 步做的人找不到对应命令。

同批还发现两件事：`scripts/buglog.sh`（8 KB bash）整个脚本只为浏览那份封版字典，且硬依赖 bash（本仓在 Windows 上跑，bash 的 PATH 抖动已经不止一次让脚本静默失败）；它里面唯一有长期价值的检查——「源码引用的 P 编号是否都在字典里」——**是在 CI 之外、靠人想起来才跑的**。

## 候选与排除

| 候选 | 结论 | 排除理由 |
|---|---|---|
| **归档降级为台账的一个生命周期阶段，由 CLI 独占**（事件归档 `archive` 命令 + 文档滚动归档各归各的触发条件） | 采用 | 台账是**唯一记账通道**（既有纪律），那它的瘦身也必须走同一条通道——否则归档动作本身就成了绕过指纹闸门的手工改文件 |
| 保持现状：`list --limit` 掩盖增长 + 人肉读 timeline.md | 排除 | 增长是**必然的**（事件流只追加是刻意设计），靠显示层截断只是把成本推给下一次查询；「归档」一词的多义性也不会自己消失 |
| 引入 Event Sourcing / 按时间的日志分片架构 | 排除 | 命中 0005 已排除的反面信号：这里没有重放、没有多订阅者、没有时间旅行查询需求。需要的只是「把已终结的部分搬走」，不是「让历史成为一等公民」 |
| 直接删掉 `timeline.md` 与全部 archive 残留，归档概念一并取消 | 排除 | 字典被源码**强耦合**（60+ 处 `P编号`，含用户可见的报错文案 `平台缺陷 P24`）。删掉它等于让一批注释与文案变成天书——那是把「文档脏」换成「代码髒」，成本更高 |
| 人维护 `platform-limits-history.md` 作为唯一的归档通道 | 排除 | 它只能归档**文档行**，管不了台账体积；而台账才是真在无限增长的那个。两者触发条件不同，硬合成一个只会又产生一个多义词 |
| 让 `archive` 直接删除旧数据（而不是搬进归档库） | 排除 | 会拆掉去重闸门：已修好的 bug 再冒出来时，主库查不到 → 又记一条 → 同一个问题被反复当新 bug 处理。归档**必须**可被去重逻辑查到 |

## 结论

**不引入新模式。** 把「归档」拆成两件各自有触发条件、产物、不变式的事，并让台账那件由 CLI 独占：

### 1. 事件归档 —— 机器执行，`archive` 命令

- **判据（全部满足才归档）**：指纹在 `handled.json` 里；`handledAt` 早于阈值（默认 `30d`）；`handledAt` 之后**没有任何事件**。→ `regressed` 的指纹永不归档。
- **产物**：事件行按 `ts` 月份分片进 `archive/events/<YYYY-MM>.jsonl`；闭环条目进 `archive/handled.json`；账本 `archive/INDEX.json`（分片 → 指纹数 / 事件数 / 时间范围 / 生成时间）。
- **主库收缩**：`errors.jsonl` 重写为剩余行，`handled.json` 只留活跃条目。
- **硬不变式**：`record` 的去重判定**必须同时查归档库**。命中归档条目时按阶段分流：
  - `--stage record` → 仍返回 `suppressed`（附 `archived: true`），计数累加在归档条目上；
  - `--stage regress` → **不能静默吞掉**。把该指纹**整块**搬回主库（闭环条目 + 它的事件，`unarchiveFingerprint()`），
    再记一条 `state=regressed`，与从未归档过的指纹行为完全一致。

  后半条是压测才发现的：一开始只把条目搬回、事件留在归档分片里，于是 `list --archived`
  打出「已归档 0 个指纹 · 1 条事件」——归档账本开始自相矛盾。**整块搬走就必须整块搬回**，
  否则归档会变成「把这笔账注销」的后门（拆掉去重闸门），而不是搬运。
- `--dry-run` 先看要搬什么；`list --archived` 查归档内容；`--all` 只管主库。

### 2. 文档滚动归档 —— 人执行，方向不变但补全指引

- `references/platform-limits.md`（12.6 KB / 20 KB）超限时，把「代码已兜住且长期未复发」的行滚进 `references/platform-limits-history.md`（冻结只读）。
- 补全那句半截指引：**新建该文件时必须同时写进 SKILL.md 的加载路径**，否则孤儿检查会红。

### 3. 上一代残留的处置

- 删 `scripts/buglog.sh`（bash 依赖 + 浏览器职责都能被更便宜地替代）。
- 删所有 `git show bd9e4da:...archive/` 取回指引。
- **保留** `references/timeline.md`，但**降级为纯编号字典**：不再自称「时间线 / 归档」，只回答「源码里的 `P24` 指什么」，正文去掉取回上一代叙述的话。
- `buglog.sh` 里那个有价值的检查（源码引用的 P 编号是否都在字典里）**迁进 vitest**——按 0005 的口径，能被 CI 守住的事实不进 bash。

## 最小落地

- **角色与职责**：`archive` 是台账的**压缩动作**，不产生新事实、不判定归属、不改指纹——只做「搬运 + 记账」；`aggregate()` / `cmdRecord` 是唯一被归档影响的两个读方（都要扩到归档库）。
- **接口所在层与依赖方向**：全部落在 `scripts/mcp-tdd.mjs`（零依赖 ESM）。归档库只被 CLI 读写，`docs/mcp-errors/` 整目录仍不入库。
- **创建与装配位置**：`LEDGER/archive/{events/<YYYY-MM>.jsonl, handled.json, INDEX.json}`；`ensure()` 一并建目录；README 模板的文件构成表补三行。
- **一次调用的时序**：`archive` → 读 `handled.json` + `errors.jsonl` → 按判据分拣 → **先写归档分片、再重写主库**（中途失败不会丢数据，最坏是重复一份）→ 重算 `INDEX.json`（从分片实际内容整算，比增量维护更不容易漂）。`INDEX.json` 只描述归档库现状，不是真相源。
- **文档侧**：SKILL.md 闭环第 8 步改名为「闭环 + 收口」，归档从「每轮必做」改为「独立节奏」并写清触发条件；`references/bookkeeping.md` 新增归档一节；`references/workflow.md` 收口段补命令。

## 成本与退出条件

- 成本：`mcp-tdd.mjs` 约 +150 行（`parseDuration` / `archivedHandled()` / `cmdArchive` / `list --archived` / help 文案）；`record` 每次多读一次 `archive/handled.json`（文件通常不存在 → 早退，热路径开销可忽略）；归档库没有索引时分片按文件序号逐个读，属 O(分片数)，分片按月产生、量级极小。
- 退出条件：若台账改用数据库或长期总量恒定（例如团队约定事件流定期整目录重建），`archive` 的存在理由消失——此时回退到「删目录 + init」，并删掉 `record` 里的归档库查询分支（`archivedHandled()` 返回 `{}` 即等价）。

## 验证

- 不变量测试（`tests/skill-doc-budget.test.ts` 同目录新增断言）：
  - **源码引用的 `P编号` 必须都在 `references/timeline.md` 的字典里**（迁自 `buglog.sh`）；扫描 `packages/**/*.ts`（排除 `dist/`）与 `.changeset/`、`mcp-server/CHANGELOG.md`。这条替代了 bash 脚本的半个职责，且从此每轮 CI 都跑。
  - 体积门禁：SKILL.md ≤ 14 KB、timeline.md ≤ 14 KB（字典封版，只该变小）。
- CLI 冒烟（`MCP_TDD_ROOT` 指向临时目录，不碰真台账；共 11 步，全绿）：
  `init` → `record` → `handle --verdict usage-error` → `archive --older-than 0d --dry-run`（不动盘）
  → `archive`（1 指纹 / 1 事件 → `events/2026-09.jsonl`，主库清零）→ `list` 显示「已归档 1」
  → `list --archived` 能查到条目 → **同指纹再 `record` 返回 `suppressed` 且带 `archived: true`**
  （去重闸门没被归档拆掉，本记录最关键的一条断言）→ **同指纹 `--stage regress` 返回 `regressed`
  且条目连同事件整块搬回主库**（`list` 见 `REGRESSED`，`list --archived` 归零且不再报「0 指纹 · N 事件」）
  → 空库 `archive` 打印「无可归档项」→ `--older-than 5x` 退出码 2。
- 边界：`regressed` 指纹不被归档（回归 run 里复发过的，判据第二条把它挡在主库）；归档库存在但主库已无对应行时幂等不崩；空分片文件在整块搬回后被删除，不留空壳。
- 指标与日志：`archive` 打印搬走的指纹数 / 事件数 / 分片名与主库剩余；`list` 头部在有归档时追加「已归档 N」；`report` 的头部加「已归档」一行，让「未决数单调下降」这条既有防膨胀判据仍然可读。
- 引擎侧实测：本轮**不涉及** `shared/` / `ui/`，无需 `pnpm build` 与重载插件；验证只到 `pnpm run typecheck` + `pnpm run test`。
