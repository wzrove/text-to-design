# 0030. MCP 服务实例一次装配、跨请求复用（目录不再按请求重建）

- **日期：** 2026-09-29
- **状态：** 已采纳（真机已复验，2026-10-15：shim→daemon 链路 + 插件上下线）
- **影响范围：** `mcp-server/`（`daemon/run.ts` 的 handler 装配、`server.ts` 去掉 `liveSessions` /
  `syncToolAvailability`、`index.ts` 的连接变化回调）、`daemon/proxy.ts`（同一不变量的 shim 侧注释）
- **相关记录：** 0002（显式注入、不要模块级可变单例）、0006（目录体积）、0016（i18n 装配期投影）
- **取代：** 无 —— 本次只新增约束，未改 0002 / 0006 / 0016 的结论

## 压力

`createMcpHandler` 的工厂是**按 HTTP 请求**调用的（SDK 类型注释：`McpServerFactory` 产出的实例服务
「one serving unit: one HTTP request under `createMcpHandler`」）。而 `buildServer` 不是零成本：
53 个工具的注册会重建一遍入参/出参 JSON Schema、i18n 投影与执行体，**实测 51.7 ms/次**
（30 次均值；热区按 registrar 是 create 17.3 / props 9.8 / components 8.6 / nodes 6.8 / manage 1.8 ms）。

代价直接落在每一次调用上（本机 127.0.0.1，各 300 次请求，插件离线走快失败路径，故不含插件往返）：

| 请求 | 现状（每请求重建） | 单工具对照 |
|---|---|---|
| `tools/call` | 50.6 ms | 2.0 ms |
| `tools/list` | 86.8 ms | 1.9 ms |

另一处同源的浪费：`server.ts` 的 `liveSessions` + `syncToolAvailability` 在插件每次上下线时
对所有会话广播 `notifications/tools/list_changed`，而**目录在同一 daemon 版本下恒定**
（固定注册清单 + 调用期平台门控）—— 那条广播从诞生起就没有内容，且按 2026-07-28 的
`subscriptions/listen` 过滤规则，未订阅的会话根本收不到。

## 候选与排除

| 候选 | 结论 | 排除理由 |
|---|---|---|
| 每 era 一份、跨请求复用实例（装配结果由调用方持有） | 采用 | — |
| 保持每请求新建，只把 schema 构造/投影预计算好 | 排除 | `registerTool` 本身就占大头（单工具 0.12–1.2 ms，53 个即 10–50 ms），预计算只挪走一部分；且要新增一层「defs → 线格式描述符」的中间表示，等于为同一份事实再造一份 |
| 进程级模块单例（把 `assembled` 放 `server.ts`） | 排除 | 撞 0002：模块级可变单例不可注入、测试里跨用例串状态。改为调用方持有局部变量 |
| 保持简单（维持每请求重建） | 排除 | 每个工具调用都要先付一次目录重建，收益与改造成本完全不成比例 |

## 结论

**不引入模式**：装配结果由调用方持有（daemon 与 shim 各持一份），用「同一实例」满足 SDK 的
per-request 工厂契约；同时删掉无内容的 `list_changed` 广播与 `liveSessions` 台账。

## 实施方案

- **目标形状（全量）**：
  - `buildServer(bridge, i18n?)` 保持**调一次产一个新实例**，不做内部缓存。
  - **daemon**（`daemon/run.ts`）：`let assembled: McpServer | null = null` 持有，
    工厂写成 `() => (assembled ??= buildServer(bridge))`。整个 daemon 进程一份实例。
    同时给 handler 传 `legacy: 'reject'`（见下方不变式）。
  - **shim**（`daemon/proxy.ts`）：早已是「每个 stdio 连接一份实例」（工厂返回闭包里的 `mcp`），
    本次只补注释说明这是同一不变量的两侧。
  - `server.ts` 删除 `liveSessions` 与 `syncToolAvailability`；连接状态变化只在 `index.ts`
    留一行日志 + 刷新/清空平台状态缓存。
- **不变式**：**一个实例只服务一个 era**。2025 的 `initialize` 握手会改写实例的 negotiated
  version，与在途的 2026-07-28 请求互相踩。47820 上的客户端只有本项目的 shim，它用
  `versionNegotiation: { mode: 'auto' }` 先探 `server/discover`（`daemon/probe.ts`），必落
  modern 路径；真来了 2025 客户端一律 `-32022 Unsupported protocol version` 拒收，
  而不是静默按老流程走。
- **本次不做**：
  - 不给 shim 的 stdio 面加 `legacy: 'reject'`：那里要服务任意 MCP 宿主（含 2025-era 客户端），
    是**有意**的双 era 入口，与 /mcp（只有自家 shim）不同。
  - 不引入实例池 / 每 era 一池：当前只有 modern 一个 era 有真实流量。
  - 不做 OTel `_meta`（traceparent / baggage）透传：目前没有发送方，按仓库纪律不为「以后可能」实现。

## 成本与退出条件

- 成本：daemon 侧多一个进程级实例引用（`assembled`），生命周期与 daemon 进程一致
  （shutdown 时 `handler.close()` 统一收）。无新增依赖、无新增网络跳数。
- 退出条件：若 /mcp 将来要直接服务**多 era 的外部客户端**（不再只服务自家 shim），
  实例复用即不成立 —— 回退到「每 era 一份实例」（SDK 工厂已带 `ctx.era`，改一行）；
  再不行回退到每请求重建（功能无差别，只是慢约 50 ms）。

## 验证

- 不变量测试：`packages/mcp-server/src/__tests__/catalog-budget.test.ts` 6 例通过
  （目录体积与占位符路径不受影响）；同包 `error-codes` / `drift-hook` / `timeout-ladder` /
  `client-label` 合计 24 例通过。
- 边界/并发/重试用例：`createMcpHandler` + 真实 HTTP + `Client(mode:'auto')` 全链路往返 ——
  现代会话建立成功、目录 53 个工具、`jsd_ping` 拿到结构化结果（插件离线 → 明确未连接）、
  连续 50 次请求计时 `tools/call` 5.0 ms / `tools/list` 3.7 ms（改造前 50.6 / 86.8 ms）；
  2025-era `initialize` → HTTP 400 `-32022`，`supported: ["2026-07-28"]`。
- 指标与日志：连接变化仍留 `连接状态变化: 插件上线|插件离线(工具目录不变)`；
  daemon 存活期的装配代价从「每请求约 50 ms」变为「每进程一次」。
- **真机（jsDesign，2026-10-15 已跑）** —— 四条判据全中，测试节点已删净（`jsd_find name:'TDD30'` → 0 条）：
  ① **链路无回归**：一轮 12 个调用（ping / create_frame / set_fill / resize / batch 两步含占位符 / find×3 / delete）全 `ok=true`，耗时 2~46 ms，**无 `forward_timeout`**（日志里最近一次还是 10-13）；
  ② **离线快失败**：关面板后 `jsd_ping` 3~5 ms 回 `{connected:false, error:"设计工具 插件未连接…"}`、`jsd_create_rectangle` 13 ms 抛同一句，**不悬挂**；日志 `请求被拒(插件未连接): ping×2 / execute` + `工具 jsd_create_rectangle 执行失败`；
  ③ **重连恢复**：重开面板后 `jsd_ping` 5~11 ms `connected:true`、`jsd_get_page` 6~13 ms 读得到画布；日志 `连接状态变化: 插件上线(工具目录不变)` + `回放离线日志 24 条`；
  ④ **目录不变**：上下线前后 `目录体积` 恒为 `56 个工具 / 328 KB`，且该行只在**一次全量 sync** 时打（`daemon/proxy.ts:67`）—— 整轮 12 次调用前后行数不变 ⇒ 目录没按请求重建；离线窗口里那次重新 sync 的工具数同样是 56。
  ⚠ 如实记两处首次探测开销：状态刚变后的**第一次**调用会等 shim→daemon 重连（一次 2550 ms、一次 589 ms），稳态是 ms 级；前者撞上 daemon 版本自检自替换（`收到 /shutdown` → 自启 → `shim: 上游请求失败,触发重连后重放` → `上游已恢复`），不是离线判定的固有代价。
