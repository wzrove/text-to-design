## 压力

用户已确认 code 仅面向设计稿转代码：Figma/jsDesign 插件选择模式后通过 Copy 节点交接提示，由外部 AI 助手读取 skills、调用画布数据处理脚本并生成/执行代码。旧方案的通用仓库开发、前后端子模式、会话与工作区控制超出需求；其“仅转代码则收窄”的退出条件已命中，本记录明确取代旧提议。

实际顶部 Copy 为 selection JSON，行 Copy 为裸 ID；selection 推送深度为 1，可能降级为最小壳。当前没有转换 skill、转换处理脚本、可靠文档身份或完整快照质量标记。证据逐项列于 [修订方案](../code-mode-design.md#1-当前-copy-链路与实际能力)。

## 候选与排除

| 候选 | 结论 | 理由 |
| --- | --- | --- |
| Copy 输出偏好 + 固定交接模板 + 外部宿主补读/处理 | 推荐 | 与真实用户操作及现有 Copy 入口直接对应；普通纯函数/数据契约足够 |
| 保留旧会话级 mode、WorkRun 与 Workspace | 排除 | 插件不调度外部任务，也不拥有聊天/代码目录，无需新持久化与授权绑定 |
| 前后端子模式 | 排除 | 静态 UI 设计不能确定后端服务；框架只是输出 profile |
| Copy 时同步拉整树/跑脚本 | 排除 | 阻塞复制手势、增加连接依赖与超时；现有浅快照不能因此变完整 |
| 覆盖全部原始 Copy 格式 | 排除 | 破坏纯 JSON/ID 用途；design 保持，code 明确增强并保留原始动作 |

## 结论

不引入模式类或通用执行框架。模式仅为面板 CopyPreferences；code 交接固定 design-to-code 意图、明确目标 ID、来源线索、有限快照与缺失说明。外部 AI 根据已发布技能/脚本契约补读、归一化与生成；画布操作默认读取/导出，生成与执行由宿主授权。

已确认的是产品定位；具体 Copy 格式、UI 动作、profile 和平台来源字段仍按 [待确认表](../code-mode-design.md#9-已确认决策与后续澄清边界) 评审。本次不实现新功能。

## 实施方案

- UI 复用 SelectionCard 与 clipboard/toast；design 顶部 JSON/行 ID 保持。code 顶部处理显式选中组，行按钮仅处理本行，另留原始 JSON/ID 动作。
- shared 新增 CopyEnvelope/CopyPreferences 数据契约，沿现有 SerializedNode，不新增业务会话/工作区。静态路由/提示字典放 shared/dicts。
- selection 元数据与节点同帧采样；未知身份/时间明确 unknown，不将 copiedAt 当 observedAt。外部 AI 按固定 IDs 分层补读，来源不确定先确认。
- MCP 保留原目录、代理、Bridge、读取与导出能力，不新增代码执行或会话控制 server/tool；完整性与来源元数据仅按实际支持做兼容增强。
- 新增 design-to-code skill 与受信数据归一化脚本的设计；当前不存在。扩展发布复制/校验，提供技能与脚本文本的同源普通资源回退，宿主负责获取、hash 校验和运行。
- 本次不改源码、实际 skills、脚本、配置、测试，不 build、不重启服务、不写画布。

## 成本与退出条件

成本为 Copy 模板/格式维护、选中来源与质量标记、技能/脚本发布及平台还原验收。需保留原始复制并处理过期、截断、资源不可读与宿主无执行能力。

若处理器没有稳定输入/重复收益，先按同一 skill 手工补读整理，不为脚本建立注册服务。回退 design 偏好/隐藏 code Copy，原画布与复制功能继续；没有会话数据库迁移或运行任务恢复负担。
