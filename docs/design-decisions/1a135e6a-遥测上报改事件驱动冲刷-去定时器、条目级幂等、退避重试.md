# 1a135e6a. 遥测上报改事件驱动冲刷:去定时器、条目级幂等、退避重试

- **日期：** 2026-10-26
- **状态：** 已采纳
- **影响范围：** `mcp-server/telemetry`(daemon)、`telemetry`(worker + DB)
- **相关记录：** N/A

## 压力

原实现用 `setInterval(flushTelemetry, 120_000)` 作唯一节奏([telemetry.ts](../../packages/mcp-server/src/telemetry.ts) 旧 39/146 行),三处实际代价:

1. **空转**:daemon 常驻数周,无错误时每 120s 仍醒一次。
2. **延迟**:错误最坏滞留 120s;fatal 才走 3s 兜底。
3. **失败无退避**:worker 401/不可用时按固定 120s 重试,永不收敛。

另有两处**数据准确性**缺口,同一批上报里已可复现:

- **在途 `count++` 丢失**:`batch = queue.slice(0, BATCH_MAX)` 是浅拷贝,元素同引用。请求体在 `fetch` 调用点同步序列化,此后网络往返内若有同名错误到达,去重命中仍在队列里的在途条目 → `count++`,但该增量已错过序列化;成功出队时整条删除,增量蒸发。
- **溢出裁剪削掉在途批次**:`queue.length > QUEUE_MAX` 时从头部 `splice`,若正发生在 flush 的网络 await 中,砍掉的正是已序列化但**尚未成功**的 `batch` 头部;随后 `queue.slice(batch.length)` 再砍一次 → 净丢若干条未发送的错误。
- **重试即重复入库**:`res.ok` 为假时队列原样保留,下轮重发同一批;worker 的 `error_reports` 无唯一约束、无幂等键,「先提交事务、后响应失败」的场景会插两行。语义是 at-least-once,不是 exactly-once。

## 候选与排除

| 候选 | 结论 | 排除理由 |
|---|---|---|
| 事件驱动延迟冲刷(首条错误后挂一次延迟 timer,不重置) | 采用 | — |
| Retry(指数退避 + 上限 + jitter) | 采用(辅助) | — |
| Idempotency(条目级 `error_id` + 唯一索引 + upsert) | 采用(辅助) | — |
| 纯惰性:只在下次 capture / 队列满时冲 | 排除 | 最后一批永远滞留 —— 没有后续错误来触发 |
| 搭 `HEARTBEAT_MS`(30s)便车 | 排除 | 本质仍是定时,且比 120s **更频繁**;把「版本提示投递」与「遥测上报」两个职责耦到一个 tick |
| 只在 fatal / shutdown 冲 | 排除 | daemon 活数周,错误全程滞留;SIGKILL 全丢 |
| 落盘 spool(崩溃恢复) | 排除 | 错误遥测无可靠性契约,SIGKILL 丢队列可接受;引持久化不成比例 |
| Circuit Breaker | 排除 | 队列上限 100 条,无资源耗尽路径;退避已足够 |
| 保持简单(原定时器) | 排除 | 空转、延迟、无退避三条代价都在,且用户明确要求去掉定时上报 |

## 结论

不引入 GoF 模式。**事件驱动延迟冲刷**为主,**Retry** 与 **Idempotency** 为辅:定时器从「常驻轮询」变成「只在队列非空时存在的延迟投递」——空队列 = 零 timer;重试带指数退避;每条错误带稳定 id 使重发幂等。

## 实施方案

- **目标形状(全量)**:
  - `captureError` 入队时为每条错误分配 `id = randomUUID()`;去重扫描**跳过 `inflight` 条目**(在途条目的 count 已随请求体定格,再加也是丢)。
  - 入队尾部:队列达 `BATCH_MAX` → 取消待发 timer 并立即冲;否则 `scheduleFlush(FLUSH_DELAY_MS = 10s)`。已挂 timer 不重置 —— 持续错误流不会饿死冲刷。
  - `flushTelemetry` 取批后把 `batch` 全标 `inflight = true`;成功用 `queue.filter(e => !e.inflight)` 出队(不依赖「前缀」假设),失败保留并 `scheduleFlush(backoff)`;`finally` 清 `inflight`。
  - 溢出裁剪改为**只裁非在途的最旧条目**。
  - 成功后退避计数归零;队列仍有剩余则 `scheduleFlush(0)` 续排空。
  - 导出 `stopTelemetry()` 置停标志并清 timer,shutdown 时调用(抑制关闭路径再挂新 timer)。
  - worker:`error_reports` 加可空 `error_id` + 唯一索引(Postgres 对 NULL 不去重,故老客户端不传 id 也不冲突);写入改 `onConflictDoUpdate` 只抬 `count = greatest(现值, excluded)`。
- **本次不做**:不落盘 spool;不做 Circuit Breaker;不动 `QUEUE_MAX`/`BATCH_MAX`;不给 `error_reports` 加「全局错误指纹」级去重(count 仍是窗口内聚合,跨批次重复出现仍是新行)。

## 成本与退出条件

- 成本:进程内多 `failCount` + `flushTimer` + 每条的 `id`/`inflight` 字段;DB 多一列 + 一个唯一索引;上报时刻不再可预测(对错误遥测无影响)。无持久化、无新依赖、无新协议。
- 退出条件:若将来要「固定节奏在线状态」类遥测,或 worker 侧要求可预测到达节奏 → 恢复 `setInterval`,删退避状态与 `inflight` 标记;`error_id` 列可保留(对旧行为无害)。

## 验证

- 不变量测试:空队列时零 `setTimeout` 调用;成功出队后队列不含任何 `inflight` 条目;同一条目的 `id` 在重试间不变。
- 边界/并发/重试用例:连续同名错误只在首条后 10s 冲一次且 `count` 聚合正确;队列达 50 立即冲;在途期间到达的同名错误**另起一条**而非加到在途条目;溢出裁剪跳过在途前缀;401/网络失败退避序列 10→20→40→…→300s 且有 jitter,成功后归零;fatal 3s 内冲完再 `exit(1)`;SIGINT 1.5s 内冲完;同 `error_id` 重发在 worker 侧只留一行且 `count` 取最大。
- 指标与日志:失败仍只留 `debug`(不升级为 error,避免遥测自身故障刷屏);worker 侧 `accepted` 仍报本批条数(含冲突跳过者,不做精确区分)。
