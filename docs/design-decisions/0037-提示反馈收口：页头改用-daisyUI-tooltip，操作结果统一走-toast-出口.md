# 0037. 提示反馈收口：页头改用 daisyUI tooltip，操作结果统一走 toast 出口

- **日期：** 2026-10-10
- **状态：** 已采纳（类型检查通过；三平台真机待验：气泡宽度/贴边、toast 层级与连点去重）
- **影响范围：** `ui/`（新增 `components/{Tooltip,Toast}.tsx`、`utils/toast.ts`；`index.css` 加一条气泡宽度规则；页头四组件 + `App.tsx`；`SelectionCard` / `ConnectionHint` / `LogDrawer` 的复制反馈）、`shared/`（i18n 增 2 键、删 2 键）
- **相关记录：** 浮层不进流沿 0014/0015（`fixed` 不参与 `PanelHeightSync` 测量）；文案键化沿 0016；「同一交互只留一个实现」与 0026 同源；模块级状态的口径取自 0002 与 `theme.ts` 的既有取舍

## 压力

两件事，共同症状都是「同一件事散在多处，各写各的」：

1. **页头五颗功能按钮的说明**全挂在原生 `title` 上。原生提示延迟约一秒、样式由宿主定，而这几句都是长句（相机锁那句 26 个字）—— 在 360 宽的面板里，长句气泡必然越出面板被裁。用户明确要求换成 tooltip。

2. **「操作成功了」有四种写法**：`SelectionCard` 把按钮文案换成 `✓`、`ConnectionHint` 换成 `✓ 已复制`、`LogDrawer` 换成 `✓`、`CapabilityCard` 的刷新干脆不出声。同一件事四份实现，且都只在**按钮自己身上**改字：复制的结果在系统剪贴板里，那点字一淡出，面板上就不剩任何痕迹；四个 `setTimeout` 的时长还各不相同（1200 / 1500）。反馈的载体一旦各写各的，文案、时长、级别都会各自漂。

## 候选与排除

| 候选 | 结论 | 排除理由 |
|---|---|---|
| 页头提示改用 daisyUI `tooltip`（气泡由 `data-tip` 的 `::before` 画） | 采用 | — |
| 保留原生 `title`，只调文案 | 排除 | 延迟、样式、越界裁切都是浏览器与宿主行为，面板侧无从修 —— 而这三条正是要解的 |
| 自绘气泡（absolute + 定位计算 + 翻转） | 排除 | 装着的 daisyUI 已提供；自绘还要自己做 hover/focus 时机、碰撞翻转与边缘收口，成本高于收益 |
| 气泡沿用 daisyUI 默认 `max-width: 20rem` | 排除 | 320px 的气泡在 360px 面板里必然越界，被根滚动容器的 overflow 裁掉（见「实施方案」） |
| 操作反馈统一走 toast（daisyUI `toast` 容器） | 采用 | — |
| 保留按钮上的 `✓` 局部态，另外再弹 toast | 排除 | 同一事实两个出口不是「更清楚」，只是两处都可能过期；「已复制」这句话只能有一个真源 |
| toast 条目用 daisyUI 的 `.alert-success` | 排除 | `.alert-*` 是**实心底 + `*-content`**，而本主题的 `*-content` 是按「淡底贴近 base-100」校准的（`index.css` 规则②），拿它配实心底在亮色下只有 2 倍出头对比度 —— 撞既有配色纪律 |
| toast 状态放 App 内部信号、逐层传 prop | 排除 | 四个调用点分处四棵子树，传下去要给每一层加 prop；而状态本来只有一份 |
| toast 走 context provider | 排除 | 调用点都在组件树内、挂载点唯一，Provider 只承担转发（同 `theme.ts` 的取舍） |
| 「已复制」同时写进日志抽屉 | 排除 | 日志是诊断通道（MCP 调用与连接事件），塞用户操作会把它变成第二本流水账 |

## 结论

**不引入模式，两张小表收口**：

- **提示**：daisyUI `tooltip` + 一个 `Tooltip` 包装组件（`data-tip`、贴边方位、包装元素的职责都只在这里）；
- **反馈**：一个模块级 toast 状态（`utils/toast.ts`）+ 一个挂载点（`ToastHost`），复制统一走 `copyWithToast`。

**弹不弹的尺子**（写死在这里，以免将来各案各判）：只在**结果不可见或极易忽略**的操作上弹 —— 复制（结果去了系统剪贴板）、相机锁（全部反馈只是换了个 14px 图标）。界面本身已经变了的（开合抽屉、切主题、清空日志、重连后状态徽章变色）不弹：那是噪声，而且第二次起就成了「每次都要划掉的东西」。

## 实施方案

- **提示（目标形状）**：`components/Tooltip.tsx` 是面板里唯一产出悬浮气泡的地方。页头五处（重连/夺回、相机锁、主题、语言、日志）都经它，同时删掉各自的 `title` 属性 —— 两套提示会先后弹两次。
  - **必须包一层元素**：`tooltip` 类自带 `display: inline-block`，直接挂到 `.btn` 上会被 `button.css` 的 `inline-flex` 盖掉（同一子层、文件在后），气泡位置就取决于样式表顺序，不可靠。包装元素成为页头里的 flex 项，故 `shrink-0` 由调用方经 `class` 传下去。
  - **气泡宽度收口**（`index.css`，**层外**规则）：daisyUI 默认 20rem 的气泡在本面板必然越界。收到 12rem 让长句折行；配合 `align="start"/"end"` 贴边，气泡才始终落在面板内（右侧工具簇贴右、左侧那颗贴左 —— 居中放两者都会有一段伸到面板外）。写层外是因为它与 daisyUI 的 `.tooltip[data-tip]:before` 同特异度，写进 `@layer utilities` 后胜负就取决于两段 CSS 的先后，改一次文件顺序便会静默失效。
  - 键盘可达由 daisyUI 的 `:has(:focus-visible)` 提供，不额外接事件；按钮的可访问名仍由各自的 `aria-label`/可见文案给出，不依赖气泡。
- **反馈（目标形状）**：`utils/toast.ts` 是唯一状态源与出口（`showToast` / `dismissToast`），`components/Toast.tsx` 是唯一挂载点，`utils/clipboard.ts` 的 `copyWithToast` 是「复制成败 → 文案 + 级别」的唯一映射。
  - 条目视觉沿用面板既有的**淡底组合**（同状态徽章、连接提示条），不用 `.alert-*` 的语义实心底。
  - 同文案（+同级）只保留最新一条并重新计时：连点复制不该糊一屏，而三条一模一样的气泡同时淡出读起来像卡顿。
  - `ToastHost` 常驻在 `App` 根节点内、`fixed` 定位，不进流 —— 弹提示不会改变 `PanelHeightSync` 量出的内容高度（0014/0015）。
- **本次不做**：（a）能力表「刷新」、日志「清空」、重连/夺回不弹 toast（尺子见上；能力表的刷新若要报成功，还得把 `refreshCapabilities` 的 `void` 改成带结果，为一个提示改契约不划算）；（b）内容级原生 `title` 保持不变 —— 能力表里的 op 说明、日志长行、启动命令是「截断文本看全文」，不是功能说明，换成气泡反而更难读。

## 成本与退出条件

- **成本**：两个组件 + 一个 store；每个按钮多一层包装元素（因此 `shrink-0` 的挂载点从按钮上移到包装元素）；一条层外的 CSS 规则（故意层外，理由写在那条规则上方）。
- **退出条件**：① 宿主若提供原生气泡 API，`Tooltip` 与那条宽度规则是唯二要删的地方，调用点不动；② daisyUI 若改 tooltip 的类名或 DOM，改动面同样只有这两处；③ toast 只在「结果不可见」的操作上使用，若某天操作本身有了更直接的可见结果，先删它的 `showToast`，别保留第二重反馈。

## 验证

- 不变量测试：`pnpm run typecheck`（三包）全绿；i18n 键集与占位符由 `tests/i18n.test.ts` 守（本次增 `toast.copy.done` / `toast.copy.failed`，删已无引用的 `conn.copied` / `selection.copied`）。
- 真机待验（需 `pnpm build` + 重载插件后确认）：① 五颗按钮悬停与键盘 focus 都出气泡，且**完整**落在面板内（最右一颗不越右缘、最左一颗不越左缘）；② 复制三处（选中卡、连接引导两条、日志行）各弹一条「已复制」；③ 连点复制只留一条；④ 相机锁切换弹提示；⑤ toast 盖在日志抽屉遮罩之上、且开合抽屉不改变面板高度。
