# 前后端共享契约与联调

仅 frontend 与 backend 双选时加载。两端共享同一份 target 和 snapshot，不复制两份设计树，不分别发明契约。

## 先对齐再实现

1. 汇总设计观察、项目已有 API/模型和用户需求，标记待确认假设。
2. 对齐字段名称、类型、必填性、单位、默认值与 unknown/mixed 的处理；对齐事件、操作、API 输入输出、错误码、加载/空/错误状态和权限边界。
3. 已有契约优先复用。需要草案时显式标注，不让前端 mock 或后端模型反向冒充已确认事实。
4. 后端领域事实缺失可暂停受阻部分；前端可复用明确草案并标依赖，但不得把草案联调写成完成。

## 联调与报告

按宿主授权和项目规则验证真实接口适配、状态映射与错误路径。分别报告：

- 前端完成项、验证与缺失；
- 后端完成项、验证与缺失；
- 共享契约状态、联调实际执行结果与未完成项。

一端代码生成成功、另一端代码生成成功或命令已发出都不等于双端联调成功。双选不批准部署、生产迁移或其他高影响动作。
